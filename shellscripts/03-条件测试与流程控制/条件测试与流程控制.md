## 1 条件测试回顾

第 2 章已详细对比过三种条件测试形式，这里做快速回顾：

| 形式 | 本质 | 特点 | 典型场景 |
|------|------|------|----------|
| `[ expr ]` | 内建命令 `test` | POSIX 兼容；需手动转义 `<` `>` | 可移植脚本 |
| `[[ expr ]]` | Bash 关键字 | 支持 `=~` 正则、`&&` `\|\|`；不做单词分割 | Bash 脚本首选 |
| `(( expr ))` | 算术求值 | 类 C 语法；变量无需 `$` 前缀 | 数值比较 |

`test` 命令与 `[ ]` 完全等价——`[ -f /etc/hosts ]` 就是 `test -f /etc/hosts`。

> ⚠️ **注意**：`[` 是一个命令，后面的 `]` 是它的最后一个参数，因此**左右必须有空格**。`[-f file]` 会报 `command not found`，这是 Shell 新手最常犯的错误。

```bash
# ✗ 错误：缺少空格
[-f /etc/hosts] && echo "exists"

# ✓ 正确
[ -f /etc/hosts ] && echo "exists"
```

> **提示**：在本章后续示例中，条件测试统一使用 `[[ ]]`。如需编写纯 POSIX 脚本，将其替换为 `[ ]` 并注意转义即可。

## 2 if 语句

`if` 是 Shell 中最基本的分支结构。它的判断依据不是"布尔值"，而是**命令的退出状态码**（Exit Status）：`0` 为真，非 `0` 为假。

### 2.1 基本形式

**if-then-fi** —— 最简单的单分支：

```bash
#!/usr/bin/env bash
config="/etc/myapp/config.yaml"

if [[ -f "$config" ]]; then
    echo "配置文件存在，加载中..."
    source "$config"
fi
```

**if-then-else-fi** —— 双分支：

```bash
#!/usr/bin/env bash
service="nginx"

if systemctl is-active --quiet "$service"; then
    echo "$service 正在运行"
else
    echo "$service 未运行，正在启动..."
    sudo systemctl start "$service"
fi
```

**if-elif-else-fi** —— 多分支：

```bash
#!/usr/bin/env bash
usage=$(df / --output=pcent | tail -1 | tr -d '% ')

if (( usage >= 90 )); then
    echo "🔴 磁盘使用率 ${usage}%，紧急告警！"
elif (( usage >= 70 )); then
    echo "🟡 磁盘使用率 ${usage}%，注意清理"
else
    echo "🟢 磁盘使用率 ${usage}%，状态正常"
fi
```

> **提示**：`if` 后面可以跟任何命令，不限于 `[ ]` 或 `[[ ]]`。例如 `if grep -q "error" /var/log/app.log; then ...` 是完全合法的。

### 2.2 单行写法

利用 `&&`（AND）和 `||`（OR）短路求值可以把简单判断写成一行。

```bash
# 文件存在则读取
[[ -f "$config" ]] && source "$config"

# 目录不存在则创建
[[ -d "$dir" ]] || mkdir -p "$dir"
```

**组合写法 `cmd && action1 || action2`**：

```bash
ping -c1 -W2 8.8.8.8 &>/dev/null && echo "网络正常" || echo "网络不通"
```

> ⚠️ **注意**：`A && B || C` **不等价于** `if A; then B; else C; fi`。当 `A` 成功但 `B` 失败时，`C` 也会执行。只在 `B` 一定成功（如 `echo`）时才安全使用此写法。

```bash
# 危险示例：如果 cp 失败，rm 也会执行
[[ -f a.txt ]] && cp a.txt /backup/ || rm a.txt
```

### 2.3 嵌套 if

当逻辑分支较多时，嵌套 `if` 可以清晰表达决策树。典型场景：根据操作系统类型选择包管理器。

```bash
#!/usr/bin/env bash

install_pkg() {
    local pkg="$1"

    if [[ "$(uname)" == "Darwin" ]]; then
        if command -v brew &>/dev/null; then
            brew install "$pkg"
        else
            echo "macOS 未安装 Homebrew，请先安装" >&2
            return 1
        fi
    elif [[ -f /etc/debian_version ]]; then
        sudo apt-get install -y "$pkg"
    elif [[ -f /etc/redhat-release ]]; then
        sudo yum install -y "$pkg"
    else
        echo "不支持的操作系统" >&2
        return 1
    fi
}

install_pkg "curl"
```

> **提示**：嵌套超过 3 层时，考虑拆分成函数或改用 `case`，可读性更好。

## 3 case 语句

当需要对**同一个变量**做多值匹配时，`case` 比一长串 `if-elif` 更清晰。

### 3.1 基本语法

```
case "$variable" in
    pattern1)
        commands
        ;;
    pattern2 | pattern3)
        commands
        ;;
    *)
        default commands
        ;;
esac
```

关键要素：
- 每个分支以 `)` 结束模式、以 `;;` 结束命令块
- `*` 是默认分支，类似其他语言的 `default`
- `|` 分隔多个模式，表示"或"

### 3.2 终止符差异

Bash 4.0+ 支持三种分支终止符：

| 终止符 | 含义 | 行为 |
|--------|------|------|
| `;;` | 终止 | 匹配后立即退出 `case`（最常用） |
| `;&` | 穿透（fall-through） | 无条件执行下一个分支的命令 |
| `;;&` | 继续匹配（fall-test） | 继续测试后续分支的模式 |

```bash
#!/usr/bin/env bash
level="warn"

case "$level" in
    error)
        echo "写入错误日志"
        ;&
    warn)
        echo "发送邮件通知"
        ;&
    info)
        echo "记录到文件"
        ;;
    *)
        echo "未知级别"
        ;;
esac
# level=warn 时输出：发送邮件通知 → 记录到文件
# 因为 ;& 让 warn 穿透到 info
```

### 3.3 通配符模式匹配

`case` 的模式支持 glob 通配符，与文件名展开相同：

| 通配符 | 含义 | 示例 |
|--------|------|------|
| `*` | 任意字符串 | `*.log` |
| `?` | 任意单个字符 | `file?.txt` |
| `[...]` | 字符集合 | `[Yy]es` |
| `\|` | 或 | `start\|begin` |

### 3.4 实战示例

**服务管理脚本**：

```bash
#!/usr/bin/env bash
service="myapp"
action="${1:?用法: $0 {start|stop|restart|status}}"

case "$action" in
    start)
        echo "启动 $service..."
        /usr/local/bin/"$service" --daemon
        ;;
    stop)
        echo "停止 $service..."
        pkill -f "$service"
        ;;
    restart)
        "$0" stop
        sleep 2
        "$0" start
        ;;
    status)
        if pgrep -f "$service" &>/dev/null; then
            echo "$service 正在运行 (PID: $(pgrep -f "$service"))"
        else
            echo "$service 未运行"
        fi
        ;;
    *)
        echo "无效操作: $action" >&2
        echo "用法: $0 {start|stop|restart|status}" >&2
        exit 1
        ;;
esac
```

**按文件扩展名执行不同操作**：

```bash
#!/usr/bin/env bash
file="$1"

case "$file" in
    *.tar.gz | *.tgz)
        tar xzf "$file"
        ;;
    *.tar.bz2)
        tar xjf "$file"
        ;;
    *.zip)
        unzip "$file"
        ;;
    *.sh)
        bash "$file"
        ;;
    *)
        echo "不支持的文件类型: $file" >&2
        exit 1
        ;;
esac
```

## 4 for 循环

### 4.1 列表形式

**语法**：`for var in list; do commands; done`

列表的来源非常灵活：

```bash
# 直接列举
for color in red green blue; do
    echo "$color"
done

# 花括号展开
for i in {1..5}; do
    echo "第 $i 次"
done

# 带步长的花括号展开
for i in {0..100..10}; do
    echo "$i%"
done

# 命令替换（注意引号问题，见 4.3 陷阱）
for user in $(awk -F: '$3 >= 1000 {print $1}' /etc/passwd); do
    echo "普通用户: $user"
done

# 数组遍历
servers=("web01" "web02" "db01")
for srv in "${servers[@]}"; do
    echo "检查 $srv ..."
done
```

**实战：批量重命名文件**——将当前目录所有 `.log` 文件加上日期前缀：

```bash
#!/usr/bin/env bash
today=$(date +%Y%m%d)

for f in *.log; do
    [[ -f "$f" ]] || continue     # 无匹配时 glob 保持字面值
    mv "$f" "${today}_${f}"
done
```

### 4.2 C 风格

当循环需要精确控制**初始值、终止条件、步进**时，C 风格 `for` 更直观。

```bash
for (( i = 1; i <= 10; i++ )); do
    echo "进度: $i / 10"
done
```

**实战：带计数器的进度提示**：

```bash
#!/usr/bin/env bash
total=50

for (( i = 1; i <= total; i++ )); do
    pct=$(( i * 100 / total ))
    printf "\r处理中... %3d%% (%d/%d)" "$pct" "$i" "$total"
    sleep 0.05
done
echo ""
echo "处理完成"
```

### 4.3 for 循环陷阱

> ⚠️ **注意**：`for f in $(ls *.txt)` 是一个经典错误。当文件名包含空格时，单词分割会把一个文件名拆成多个 token。

```bash
# 假设目录有文件 "my report.txt"
for f in $(ls *.txt); do
    echo "处理: $f"
done
# 输出：
#   处理: my
#   处理: report.txt   ← 文件名被拆开了！
```

**正确做法**：

```bash
# 方法 1：直接使用 glob（推荐）
for f in *.txt; do
    [[ -e "$f" ]] || continue
    echo "处理: $f"
done

# 方法 2：while read（处理更复杂的场景）
find . -name "*.txt" -print0 | while IFS= read -r -d '' f; do
    echo "处理: $f"
done
```

## 5 while 和 until 循环

### 5.1 while 基本用法

`while` 在条件为**真**时反复执行循环体。

```bash
count=1
while (( count <= 5 )); do
    echo "第 $count 次"
    (( count++ ))
done
```

**逐行读取文件**是 `while read` 最经典的用途：

```bash
while IFS= read -r line; do
    echo ">> $line"
done < /etc/hosts
```

各参数的作用：

| 参数 | 作用 |
|------|------|
| `IFS=` | 保留行首行尾空白 |
| `-r` | 禁止反斜杠转义 |
| `< file` | 从文件重定向输入 |

> ⚠️ **注意**：如果文件最后一行没有换行符，`read` 返回非 0 但 `line` 变量仍有内容。加一个额外判断可处理这种边界情况：

```bash
while IFS= read -r line || [[ -n "$line" ]]; do
    echo "$line"
done < data.txt
```

**实战：监控日志文件**——实时检测错误关键字：

```bash
#!/usr/bin/env bash
logfile="/var/log/app/error.log"

tail -F "$logfile" | while IFS= read -r line; do
    if [[ "$line" == *"CRITICAL"* ]]; then
        echo "[$(date '+%H:%M:%S')] 严重错误: $line"
        # 可在此发送告警通知
    fi
done
```

### 5.2 until 循环

`until` 与 `while` 逻辑相反：条件为**假**时执行，条件为**真**时退出。适合"等待某个条件成立"的场景。

**实战：等待服务端口就绪**：

```bash
#!/usr/bin/env bash
host="127.0.0.1"
port=3306
timeout=30
elapsed=0

until nc -z "$host" "$port" 2>/dev/null; do
    if (( elapsed >= timeout )); then
        echo "超时：${host}:${port} 在 ${timeout}s 内未就绪" >&2
        exit 1
    fi
    echo "等待 ${host}:${port} ... (${elapsed}s)"
    sleep 2
    (( elapsed += 2 ))
done

echo "${host}:${port} 已就绪"
```

### 5.3 无限循环

两种常见写法，效果相同：

```bash
# 写法 1
while true; do
    # ...
    sleep 1
done

# 写法 2（: 是内建命令，永远返回 0）
while :; do
    # ...
    sleep 1
done
```

**实战：守护进程式监控脚本**——每 30 秒检查一次服务状态并自动重启：

```bash
#!/usr/bin/env bash
service="myapp"
interval=30

while true; do
    if ! pgrep -f "$service" &>/dev/null; then
        echo "[$(date)] $service 已停止，正在重启..."
        /usr/local/bin/"$service" --daemon
    fi
    sleep "$interval"
done
```

> **提示**：生产环境中应使用 `systemd` 或 `supervisord` 管理进程，上面的脚本适合临时应急或开发测试。

## 6 select 菜单

`select` 自动生成**编号菜单**，非常适合简单的交互式选择。

```
select var in list; do
    commands
    break
done
```

通过 **`PS3`** 变量可自定义提示符（默认为 `#?`）。

**实战：交互式服务器选择菜单**：

```bash
#!/usr/bin/env bash
PS3="请选择目标服务器 (输入序号): "

servers=("web01 - 10.0.1.1" "web02 - 10.0.1.2" "db01 - 10.0.2.1" "退出")

select choice in "${servers[@]}"; do
    case "$choice" in
        "退出")
            echo "已退出"
            break
            ;;
        "")
            echo "无效选择，请重试"
            ;;
        *)
            ip="${choice##* }"
            echo "正在连接 $ip ..."
            ssh "admin@$ip"
            break
            ;;
    esac
done
```

运行效果：

```
1) web01 - 10.0.1.1
2) web02 - 10.0.1.2
3) db01 - 10.0.2.1
4) 退出
请选择目标服务器 (输入序号): 2
正在连接 10.0.1.2 ...
```

> **提示**：`select` 循环不会自动退出，必须在合适位置加 `break`，否则会反复显示菜单。

## 7 循环控制

**`break`** 立即退出循环，**`continue`** 跳过本次迭代进入下一次。

```bash
# break —— 找到目标文件后立即退出
for f in /var/log/*.log; do
    if [[ -s "$f" ]] && grep -q "FATAL" "$f"; then
        echo "发现致命错误: $f"
        break
    fi
done

# continue —— 跳过非普通文件
for item in /opt/*; do
    [[ -f "$item" ]] || continue
    echo "处理文件: $item"
done
```

**`break N` / `continue N`** 可以控制多层嵌套循环（`N` 表示要跳出的层数）：

```bash
for dir in /data/*/; do
    for file in "$dir"*.csv; do
        [[ -e "$file" ]] || continue 2   # 无匹配时跳到外层下一个目录
        echo "处理: $file"
    done
done
```

**实战：遍历目录树，跳过隐藏目录**：

```bash
#!/usr/bin/env bash
root="${1:-.}"

while IFS= read -r -d '' dir; do
    basename=$(basename "$dir")
    # 跳过隐藏目录
    if [[ "$basename" == .* ]]; then
        continue
    fi
    file_count=$(find "$dir" -maxdepth 1 -type f | wc -l)
    echo "$dir: ${file_count} 个文件"
done < <(find "$root" -type d -print0)
```

## 8 getopts 参数解析

手工解析 `$1`、`$2` 很快会变得混乱。**`getopts`** 是 Bash 内建的选项解析工具，遵循 POSIX 约定。

**基本语法**：

```bash
while getopts "optstring" opt; do
    case "$opt" in
        # 处理各选项
    esac
done
shift $((OPTIND - 1))   # 移除已解析的选项，剩余参数在 $@
```

- **`optstring`**：选项字母的集合。字母后加 `:` 表示该选项需要参数
- **`OPTARG`**：当前选项的参数值
- **`OPTIND`**：下一个待处理参数的索引

**实战：完整的带帮助信息的脚本参数解析**：

```bash
#!/usr/bin/env bash
set -euo pipefail

VERSION="1.0.0"
verbose=false
output="/dev/stdout"
count=10

usage() {
    cat <<EOF
用法: $(basename "$0") [选项] <输入文件>

选项:
  -o FILE   输出文件（默认: 标准输出）
  -n NUM    处理行数（默认: 10）
  -v        详细输出
  -V        显示版本
  -h        显示帮助

示例:
  $(basename "$0") -n 20 -v -o result.txt input.log
EOF
}

while getopts ":o:n:vVh" opt; do
    case "$opt" in
        o) output="$OPTARG" ;;
        n) count="$OPTARG" ;;
        v) verbose=true ;;
        V) echo "$VERSION"; exit 0 ;;
        h) usage; exit 0 ;;
        :)
            echo "错误: -${OPTARG} 需要参数" >&2
            exit 1
            ;;
        \?)
            echo "错误: 未知选项 -${OPTARG}" >&2
            usage >&2
            exit 1
            ;;
    esac
done
shift $((OPTIND - 1))

# 检查必需的位置参数
if [[ $# -lt 1 ]]; then
    echo "错误: 缺少输入文件" >&2
    usage >&2
    exit 1
fi

input="$1"
$verbose && echo "参数: input=$input, output=$output, count=$count"
head -n "$count" "$input" > "$output"
```

> **提示**：`optstring` 以 `:` 开头（如 `":o:n:vVh"`）表示**静默模式**——无效选项不会输出默认错误信息，而是将选项字母存入 `$OPTARG` 以便自行处理。

**getopts 的局限性**：

| 特性 | `getopts`（Bash 内建） | `getopt`（外部命令） |
|------|------------------------|---------------------|
| 长选项 `--name` | ❌ 不支持 | ✅ 支持 |
| 选项和参数混排 | ❌ 遇到非选项即停止 | ✅ 自动重排 |
| 可移植性 | ✅ POSIX 标准 | ⚠️ GNU 版与 BSD 版行为不同 |

如果需要长选项，可使用 GNU `getopt`（注意不是 `getopts`）：

```bash
# GNU getopt 用法概览
opts=$(getopt -o "o:n:vh" --long "output:,count:,verbose,help" -- "$@")
eval set -- "$opts"
while true; do
    case "$1" in
        -o|--output) output="$2"; shift 2 ;;
        -n|--count)  count="$2";  shift 2 ;;
        -v|--verbose) verbose=true; shift ;;
        -h|--help)   usage; exit 0 ;;
        --) shift; break ;;
    esac
done
```

## 9 综合实战

下面用一个完整的**服务器健康检查脚本**把本章所有知识点串联起来。

```bash
#!/usr/bin/env bash
#
# healthcheck.sh — 批量检查服务器连通性
#
set -euo pipefail

# ─── 默认值 ──────────────────────────────────────
hosts_file=""
timeout=3
verbose=false
ok_count=0
fail_count=0
total=0

# ─── 帮助信息 ────────────────────────────────────
usage() {
    cat <<EOF
用法: $(basename "$0") -h <主机列表文件> [-t 超时秒数] [-v]

选项:
  -h FILE   主机列表文件（每行一个 IP 或主机名，# 开头为注释）
  -t SEC    ping 超时时间，默认 3 秒
  -v        详细输出模式

示例:
  $(basename "$0") -h servers.txt -t 5 -v
EOF
}

# ─── 参数解析（getopts） ─────────────────────────
while getopts ":h:t:v" opt; do
    case "$opt" in
        h) hosts_file="$OPTARG" ;;
        t) timeout="$OPTARG" ;;
        v) verbose=true ;;
        :)
            echo "错误: -${OPTARG} 需要参数" >&2
            exit 1
            ;;
        \?)
            echo "错误: 未知选项 -${OPTARG}" >&2
            usage >&2
            exit 1
            ;;
    esac
done
shift $((OPTIND - 1))

# ─── 参数校验（if） ──────────────────────────────
if [[ -z "$hosts_file" ]]; then
    echo "错误: 必须通过 -h 指定主机列表文件" >&2
    usage >&2
    exit 1
fi

if [[ ! -f "$hosts_file" ]]; then
    echo "错误: 文件不存在: $hosts_file" >&2
    exit 1
fi

# ─── 检查单个主机（函数 + case） ─────────────────
check_host() {
    local host="$1"
    local result

    if ping -c 1 -W "$timeout" "$host" &>/dev/null; then
        result="OK"
    else
        result="FAIL"
    fi

    case "$result" in
        OK)
            (( ok_count++ ))
            $verbose && echo "  ✓ $host — 连通"
            ;;
        FAIL)
            (( fail_count++ ))
            echo "  ✗ $host — 不可达"
            ;;
    esac
}

# ─── 主循环：逐行读取主机列表（while read） ─────
echo "===== 服务器健康检查 ====="
echo "主机列表: $hosts_file"
echo "超时时间: ${timeout}s"
echo "─────────────────────────"

while IFS= read -r line || [[ -n "$line" ]]; do
    # 跳过空行和注释
    [[ -z "$line" || "$line" == \#* ]] && continue

    (( total++ ))
    check_host "$line"
done < "$hosts_file"

# ─── 结果汇总 ─────────────────────────────────────
echo "─────────────────────────"
echo "汇总: 共 $total 台"
echo "  连通: $ok_count"
echo "  失败: $fail_count"

if (( fail_count > 0 )); then
    exit 1
fi
```

**主机列表文件 `servers.txt` 示例**：

```
# Web 服务器
10.0.1.1
10.0.1.2

# 数据库服务器
10.0.2.1
```

**运行方式**：

```bash
chmod +x healthcheck.sh
./healthcheck.sh -h servers.txt -t 5 -v
```

脚本中用到的知识点：

```
getopts ─── 参数解析（第 8 节）
if      ─── 参数校验、连通性判断（第 2 节）
case    ─── 结果分发处理（第 3 节）
while   ─── 逐行读取文件（第 5 节）
continue─── 跳过注释行（第 7 节，隐含在 && continue）
(( ))   ─── 计数器和数值比较（第 1 节回顾）
```

## 10 小结

1. **`if` 判断的是退出状态码**，不是字符串"true/false"。任何命令都可以作为 `if` 的条件
2. **`A && B || C` 不是 `if-else`**——当 `B` 失败时 `C` 也会执行，仅在 `B` 必然成功时安全使用
3. **`case` 适合多值匹配**，支持 glob 通配符和 `|` 或运算；Bash 4.0+ 的 `;&` 和 `;;&` 提供穿透与继续匹配能力
4. **`for` 循环的列表形式灵活**但要警惕单词分割——用 glob 而非 `$(ls)` 遍历文件
5. **`while IFS= read -r line`** 是逐行处理文件的标准模式，加 `|| [[ -n "$line" ]]` 处理无尾换行
6. **`until` 适合"等待条件成立"**的场景，与 `while` 逻辑互补
7. **`select` 快速构建编号菜单**，记得加 `break` 退出循环
8. **`break N` / `continue N`** 可控制多层嵌套循环的跳转
9. **`getopts` 是 POSIX 标准的选项解析器**，足以应对短选项场景；长选项需求可使用 GNU `getopt`
10. **综合实战中的模式**（参数解析 → 校验 → 主循环 → 结果汇总）是运维脚本的通用骨架

## 11 动手练习

1. **磁盘告警脚本**：编写脚本遍历所有挂载点（`df` 输出），使用 `if-elif` 根据使用率输出绿/黄/红三级状态。支持 `-t <阈值>` 参数自定义黄色警告阈值（默认 70%）

2. **日志分析器**：编写脚本接受日志文件路径作为参数，用 `while read` 逐行读取，统计 `INFO`、`WARN`、`ERROR` 各级别的出现次数，最后用 `case` 根据 `ERROR` 占比决定是否告警

3. **批量文件整理**：编写脚本扫描指定目录下的所有文件，用 `case` 根据扩展名将文件移动到对应子目录（`.jpg`/`.png` → `images/`，`.log` → `logs/`，`.sh` → `scripts/`，其他 → `misc/`）。支持 `-n` 干运行模式（只打印操作不实际移动）

4. **交互式数据库备份**：编写脚本用 `select` 让用户选择数据库名，用 `getopts` 解析 `-o <输出目录>` 和 `-c`（压缩）选项，然后用 `for` 循环对选中的数据库执行 `mysqldump`（命令可用 `echo` 模拟），并在 `while` 循环中显示进度
