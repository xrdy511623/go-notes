## 1 退出状态码

### 1.1 $? 的含义与约定

每条命令执行完毕后，Shell 会在特殊变量 **`$?`** 中保存该命令的**退出状态码（Exit Status）**——一个 0-255 的整数。

```bash
# 成功的命令返回 0
ls /tmp > /dev/null
echo $?   # 0

# 失败的命令返回非零值
ls /nonexistent 2> /dev/null
echo $?   # 2
```

约定很简单：**0 表示成功，非零表示失败**。不同的非零值携带不同的语义信息。

### 1.2 exit 命令

**`exit`** 用于显式终止脚本并设置退出码。省略参数时，退出码为最后一条命令的 `$?`。

```bash
#!/bin/bash

if [ ! -f "$1" ]; then
    echo "Error: file '$1' not found" >&2
    exit 1
fi

# 正常结束
exit 0
```

> **提示**：始终通过 `exit` 明确设置退出码，不要依赖隐式行为。这让调用方（其他脚本、CI 系统）能可靠判断执行结果。

### 1.3 return vs exit

在**函数**内部，`return` 和 `exit` 的行为截然不同：

| 命令     | 作用范围         | 效果                           |
| -------- | ---------------- | ------------------------------ |
| `return` | 当前函数         | 结束函数执行，设置函数返回值   |
| `exit`   | 整个脚本进程     | 终止整个脚本，设置脚本退出码   |

```bash
check_file() {
    if [ ! -f "$1" ]; then
        # return 只退出函数，脚本继续执行
        return 1
    fi
    return 0
}

check_file "/nonexistent"
echo "脚本仍在运行, 函数返回值: $?"
```

> ⚠️ **注意**：在函数中误用 `exit` 会导致整个脚本退出，而不是仅退出函数。这是 Shell 新手常犯的错误。

### 1.4 常用退出码参考表

| 退出码   | 含义                                   | 示例                              |
| -------- | -------------------------------------- | --------------------------------- |
| `0`      | 成功                                   | 命令正常完成                      |
| `1`      | 一般性错误                             | 除法运算错误、权限不足等          |
| `2`      | Shell 内建命令误用                     | 缺少关键参数                      |
| `126`    | 命令存在但不可执行                     | 权限不足（缺少 `+x`）            |
| `127`    | 命令未找到                             | `PATH` 中无此命令                 |
| `128`    | `exit` 参数无效                        | `exit 3.14`                       |
| `128+N`  | 被信号 N 终止                          | `128+9=137`（SIGKILL）            |
| `130`    | 被 Ctrl+C 终止（SIGINT=2）            | `128+2=130`                       |
| `255`    | 退出码超出范围                         | `exit -1` 实际为 255              |

> **提示**：自定义脚本建议用 `1` 表示一般错误，用 `2` 表示参数错误。保留 126+ 给系统使用。

## 2 set 命令：防御性编程基石

### 2.1 set -e（errexit）

**`set -e`** 让脚本在任何命令返回非零退出码时立即终止，而不是默认继续执行。

```bash
#!/bin/bash
set -e

cp important.conf /backup/     # 若 cp 失败，脚本立即退出
echo "备份完成"                  # 不会执行到这里
```

但 `-e` 并不是万能的。以下场景中命令失败**不会**触发退出：

```bash
set -e

# 1. 在 if 条件中——不触发退出
if grep -q "pattern" file.txt; then
    echo "found"
fi

# 2. 在 || 或 && 链中——不触发退出
grep -q "pattern" file.txt || echo "not found"

# 3. 在子 Shell 中——子 Shell 退出，父 Shell 不受影响
(false)    # 子 Shell 退出，但父脚本可能继续（行为因 Bash 版本而异）
```

**实战坑：`grep` 未匹配导致意外退出**

`grep` 在未匹配到任何行时返回 `1`，这在 `set -e` 下会直接终止脚本：

```bash
set -e

# 危险：如果 file.txt 中没有 "ERROR"，脚本立即退出
count=$(grep -c "ERROR" /var/log/app.log)

# 安全写法 1：用 || true 吞掉错误
count=$(grep -c "ERROR" /var/log/app.log || true)

# 安全写法 2：用 if 包裹
if grep -q "ERROR" /var/log/app.log; then
    echo "发现错误日志"
fi
```

### 2.2 set -u（nounset）

**`set -u`** 在引用未定义变量时报错并退出，防止拼写错误导致的隐性 Bug。

```bash
#!/bin/bash
set -u

echo "$UNDEFINED_VAR"    # 报错：UNDEFINED_VAR: unbound variable
```

与**默认值语法**配合使用，可以安全地处理可选变量：

```bash
set -u

# ${var:-default} ：var 未定义或为空时使用 default
log_level="${LOG_LEVEL:-INFO}"

# ${var:=default} ：var 未定义或为空时赋值并使用 default
: "${TIMEOUT:=30}"

# 检查位置参数是否存在
input_file="${1:-}"
if [ -z "$input_file" ]; then
    echo "Usage: $0 <file>" >&2
    exit 2
fi
```

### 2.3 set -o pipefail

默认情况下，管道的退出码是**最后一个**命令的退出码。这意味着前面的命令失败会被静默忽略。

```bash
# 没有 pipefail：即使 grep 失败，管道返回 0（wc 成功）
grep "ERROR" /nonexistent 2>/dev/null | wc -l
echo $?   # 0
```

**`set -o pipefail`** 让管道返回**最后一个失败命令**的退出码：

```bash
set -o pipefail

grep "ERROR" /nonexistent 2>/dev/null | wc -l
echo $?   # 2（grep 的退出码）
```

> ⚠️ **注意**：开启 `pipefail` 后，`set -e` 才能正确捕获管道中间环节的错误。两者应配合使用。

### 2.4 set -x（xtrace）

**`set -x`** 在执行每条命令前将其打印到 stderr，是最基础的调试手段。

```bash
#!/bin/bash
set -x

name="world"
echo "Hello, $name"
```

输出：

```
+ name=world
+ echo 'Hello, world'
Hello, world
```

详细的调试技术见[第 5 节](#5-调试技术)。

### 2.5 推荐的脚本开头模板

```bash
#!/usr/bin/env bash
set -euo pipefail
```

这四个字母 `euo pipefail` 构成了防御性 Shell 编程的基石：

```
set -e          → 命令失败立即退出
set -u          → 引用未定义变量报错
set -o pipefail → 管道中任一命令失败则整个管道失败
```

对于需要调试的脚本，加上 `-x`：

```bash
#!/usr/bin/env bash
set -euxo pipefail
```

### 2.6 选项对比表

| 选项             | 简写       | 作用                         | 不生效的场景                     | 常见陷阱                           |
| ---------------- | ---------- | ---------------------------- | -------------------------------- | ---------------------------------- |
| `errexit`        | `-e`       | 命令失败时退出脚本           | `if`、`||`、`&&`、子 Shell       | `grep` 无匹配返回 1               |
| `nounset`        | `-u`       | 引用未定义变量报错           | `${var:-}`、`${var:=}` 有默认值  | `$@` 在无参数时报错（用 `"$@"`）  |
| `pipefail`       | 无         | 管道返回最后一个失败的退出码 | 单条命令（非管道）               | 与 `head` 配合时 SIGPIPE 触发退出 |
| `xtrace`         | `-x`       | 打印每条执行的命令           | 始终生效                         | 可能泄露密码等敏感变量             |

## 3 trap 信号处理

### 3.1 基本语法

**`trap`** 命令用于在脚本收到指定**信号（Signal）**或触发特定**伪信号**时执行回调。

```bash
# 语法
trap 'commands' SIGNAL [SIGNAL...]

# 重置为默认行为
trap - SIGNAL

# 忽略信号
trap '' SIGNAL
```

### 3.2 常用信号

| 信号      | 编号  | 触发条件                       | 典型用途           |
| --------- | ----- | ------------------------------ | ------------------ |
| `EXIT`    | —     | 脚本退出（任何方式）           | 清理临时文件       |
| `ERR`     | —     | 命令返回非零退出码             | 记录错误上下文     |
| `INT`     | 2     | 用户按 Ctrl+C                  | 优雅中断           |
| `TERM`    | 15    | `kill` 命令（默认信号）        | 优雅终止           |
| `HUP`     | 1     | 终端断开                       | 重新加载配置       |
| `DEBUG`   | —     | 每条命令执行前触发             | 高级调试           |

> **提示**：`EXIT` 和 `ERR` 是 Bash **伪信号**（pseudo-signal），不是真正的 Unix 信号，只在 Bash 中有效。

### 3.3 trap EXIT：清理临时文件

`trap ... EXIT` 是最常用的模式——无论脚本正常结束、出错退出还是被信号终止，清理逻辑都会执行。

```bash
#!/usr/bin/env bash
set -euo pipefail

tmpdir=$(mktemp -d)
trap 'rm -rf "$tmpdir"' EXIT

# 在临时目录中工作
cp /etc/hosts "$tmpdir/hosts_backup"
echo "临时文件: $tmpdir/hosts_backup"

# 脚本结束时 $tmpdir 自动删除，无需手工清理
```

### 3.4 trap ERR：错误处理函数

结合 `set -e`，`trap ERR` 可以在错误发生时自动输出上下文信息。

```bash
#!/usr/bin/env bash
set -euo pipefail

error_handler() {
    local exit_code=$?
    local line_no=$1
    echo "ERROR: 脚本在第 ${line_no} 行失败，退出码: ${exit_code}" >&2
    echo "失败的命令: ${BASH_COMMAND}" >&2
}

trap 'error_handler $LINENO' ERR

# 模拟一个失败
echo "开始处理..."
cp /nonexistent/file /tmp/   # 这里会触发 ERR trap
echo "这行不会执行"
```

输出：

```
开始处理...
cp: /nonexistent/file: No such file or directory
ERROR: 脚本在第 14 行失败，退出码: 1
失败的命令: cp /nonexistent/file /tmp/
```

### 3.5 实战示例

**示例 1：创建临时目录，退出时自动清理**

```bash
#!/usr/bin/env bash
set -euo pipefail

cleanup() {
    local exit_code=$?
    if [ -d "${WORK_DIR:-}" ]; then
        rm -rf "$WORK_DIR"
        echo "已清理临时目录: $WORK_DIR" >&2
    fi
    exit "$exit_code"
}

trap cleanup EXIT

WORK_DIR=$(mktemp -d "${TMPDIR:-/tmp}/myapp.XXXXXXXXXX")
echo "工作目录: $WORK_DIR"

# 模拟业务逻辑
echo "processing..." > "$WORK_DIR/status"
sleep 1
echo "完成"
```

**示例 2：捕获 Ctrl+C 实现优雅退出**

```bash
#!/usr/bin/env bash
set -euo pipefail

interrupted=false

handle_sigint() {
    echo ""
    echo "收到 SIGINT，正在优雅退出..." >&2
    interrupted=true
}

trap handle_sigint INT

echo "服务运行中（按 Ctrl+C 停止）..."
while [ "$interrupted" = false ]; do
    echo "$(date '+%H:%M:%S') 心跳"
    sleep 2
done

echo "清理完成，再见"
```

**示例 3：ERR trap 输出错误行号和命令**

```bash
#!/usr/bin/env bash
set -euo pipefail

on_error() {
    local exit_code=$?
    local line=$1
    local cmd="${BASH_COMMAND}"
    cat >&2 <<-MSG
	┌─────────────────────────────────
	│ ERROR at line ${line}
	│ Command: ${cmd}
	│ Exit code: ${exit_code}
	│ Script: ${BASH_SOURCE[0]}
	└─────────────────────────────────
	MSG
}

trap 'on_error $LINENO' ERR

echo "步骤 1: 检查环境"
ls /tmp > /dev/null

echo "步骤 2: 下载配置"
curl -sf "http://invalid.example.com/config" -o /dev/null

echo "步骤 3: 不会到这里"
```

## 4 错误处理模式

### 4.1 短路模式

用 `||` 在命令失败时执行错误处理。适合单行快速处理。

```bash
# 命令失败时输出错误并退出
cd /opt/app || { echo "无法进入 /opt/app" >&2; exit 1; }

# 赋值场景
config=$(cat /etc/app.conf) || { echo "读取配置失败" >&2; exit 1; }
```

> ⚠️ **注意**：花括号内的命令需要以 `;` 结尾，且花括号前后必须有空格。

### 4.2 条件判断模式

当需要更复杂的错误处理逻辑时使用 `if`。

```bash
if ! cp "$src" "$dst" 2>/dev/null; then
    echo "复制失败: $src -> $dst" >&2
    echo "尝试使用 sudo..."
    sudo cp "$src" "$dst" || exit 1
fi
```

### 4.3 die 函数模式

封装一个 `die` 函数，统一错误输出格式，减少重复代码。

```bash
die() {
    echo "FATAL: $*" >&2
    exit 1
}

# 使用
[ -f "$config_file" ] || die "配置文件 $config_file 不存在"
[ -d "$output_dir" ]  || die "输出目录 $output_dir 不存在"

command -v jq > /dev/null || die "缺少依赖: jq，请先安装"
```

增强版——携带退出码：

```bash
die() {
    local code="${1:-1}"
    shift
    echo "FATAL [$code]: $*" >&2
    exit "$code"
}

die 2 "参数不足，用法: $0 <input> <output>"
```

### 4.4 retry 函数模式

对可能暂时性失败的操作（网络请求、服务连接）进行自动重试。

```bash
retry() {
    local max_attempts=$1
    local delay=$2
    shift 2
    local cmd=("$@")

    local attempt=1
    while [ "$attempt" -le "$max_attempts" ]; do
        if "${cmd[@]}"; then
            return 0
        fi
        echo "WARN: 第 ${attempt}/${max_attempts} 次尝试失败，${delay}s 后重试..." >&2
        sleep "$delay"
        ((attempt++))
    done

    echo "ERROR: ${cmd[*]} 在 ${max_attempts} 次尝试后仍然失败" >&2
    return 1
}

# 使用：最多重试 5 次，每次间隔 3 秒
retry 5 3 curl -sf "http://api.example.com/health"
```

### 4.5 模式选择决策表

| 场景                         | 推荐模式       | 示例                                       |
| ---------------------------- | -------------- | ------------------------------------------ |
| 单条命令失败即退出           | 短路 `\|\|`    | `cd /app \|\| exit 1`                      |
| 失败后需要替代逻辑           | `if ! cmd`     | 先普通复制，失败后 sudo                    |
| 多处需要统一的错误退出       | `die` 函数     | 参数校验、依赖检查                         |
| 暂时性故障需要重试           | `retry` 函数   | 网络请求、服务连接                         |
| 需要详细错误上下文           | `trap ERR`     | 记录行号、命令、调用栈                     |

## 5 调试技术

### 5.1 set -x 跟踪

**全局开启**

```bash
#!/bin/bash
set -x
# 整个脚本的每条命令都会被打印
```

**局部开启**——只对可疑代码段启用跟踪：

```bash
# 正常代码...

set -x
# 这段代码的执行过程会被打印到 stderr
process_data "$input"
validate_output "$output"
set +x

# 后续代码不再打印跟踪
```

**定制 PS4 变量**

默认的跟踪前缀是 `+ `，信息量太少。通过自定义 **`PS4`**，可以在跟踪输出中显示文件名、行号、函数名甚至时间戳：

```bash
export PS4='+${BASH_SOURCE[0]}:${LINENO}:${FUNCNAME[0]:+${FUNCNAME[0]}(): }'
set -x
```

输出效果：

```
+./deploy.sh:12:main(): config_file=/etc/app.conf
+./deploy.sh:13:main(): validate_config /etc/app.conf
+./deploy.sh:25:validate_config(): echo 'config ok'
```

带时间戳的版本：

```bash
export PS4='+$(date "+%H:%M:%S") ${BASH_SOURCE[0]}:${LINENO}: '
```

**外部启用**——不修改脚本，直接用 `bash -x` 运行：

```bash
bash -x script.sh arg1 arg2
```

### 5.2 bashdb 调试器

**bashdb** 是一个类似 GDB 的 Bash 脚本调试器，支持断点、单步执行和变量检查。

安装：

```bash
# macOS
brew install bashdb

# Ubuntu/Debian
sudo apt-get install bashdb
```

基本用法：

```bash
# 启动调试
bashdb script.sh

# 常用命令
# n / next     → 单步执行（跳过函数）
# s / step     → 单步执行（进入函数）
# b 15         → 在第 15 行设置断点
# c / continue → 继续执行到下一个断点
# p $var       → 打印变量值
# l            → 显示当前代码上下文
# q / quit     → 退出调试器
```

> **提示**：对于简单脚本，`set -x` 通常足够。`bashdb` 更适合调试复杂的多函数、多文件脚本。

### 5.3 日志函数

生产脚本需要结构化的日志输出，而不是随意的 `echo`。

```bash
LOG_LEVEL="${LOG_LEVEL:-INFO}"

log() {
    local level="$1"
    shift
    local timestamp
    timestamp=$(date '+%Y-%m-%d %H:%M:%S')

    # 级别过滤
    case "$LOG_LEVEL" in
        DEBUG) allowed="DEBUG INFO WARN ERROR" ;;
        INFO)  allowed="INFO WARN ERROR" ;;
        WARN)  allowed="WARN ERROR" ;;
        ERROR) allowed="ERROR" ;;
        *)     allowed="INFO WARN ERROR" ;;
    esac

    if [[ " $allowed " != *" $level "* ]]; then
        return 0
    fi

    # 输出到 stderr，不污染 stdout 的数据流
    echo "[$timestamp] [$level] $*" >&2
}

log_debug() { log "DEBUG" "$@"; }
log_info()  { log "INFO"  "$@"; }
log_warn()  { log "WARN"  "$@"; }
log_error() { log "ERROR" "$@"; }
```

使用示例：

```bash
log_info "开始处理文件: $input_file"
log_debug "当前行数: $line_count"
log_warn "磁盘使用率超过 80%"
log_error "无法连接数据库: $db_host"
```

**同时输出到文件**——用 `tee` 将 stderr 同时写入日志文件：

```bash
LOG_FILE="/var/log/myapp.log"

log() {
    local level="$1"
    shift
    local timestamp
    timestamp=$(date '+%Y-%m-%d %H:%M:%S')
    local msg="[$timestamp] [$level] $*"
    echo "$msg" >&2
    echo "$msg" >> "$LOG_FILE"
}
```

## 6 临时文件安全管理

### 6.1 mktemp 的正确用法

**`mktemp`** 使用随机后缀创建临时文件或目录，避免文件名冲突和安全问题。

```bash
# 创建临时文件
tmpfile=$(mktemp)
echo "$tmpfile"    # /tmp/tmp.aB3xK9mZ1w

# 创建临时目录
tmpdir=$(mktemp -d)
echo "$tmpdir"     # /tmp/tmp.Pq7rL2nX4v

# 自定义前缀和模板
tmpfile=$(mktemp "${TMPDIR:-/tmp}/myapp.XXXXXXXXXX")
```

### 6.2 为什么不能用手工路径

硬编码临时文件路径存在**竞态条件（Race Condition）**安全漏洞：

```bash
# ❌ 危险写法：可预测的文件名
tmpfile="/tmp/myfile.$$"
echo "data" > "$tmpfile"
```

攻击场景：

```
1. 攻击者预测文件名 /tmp/myfile.12345
2. 攻击者提前创建该文件的符号链接 → /etc/passwd
3. 你的脚本向该路径写入，实际覆盖了 /etc/passwd
```

`mktemp` 使用随机后缀并以 `O_EXCL` 方式原子创建文件，从根本上避免了这个问题。

### 6.3 标准模式与实战示例

**标准模式**：`mktemp -d` + `trap EXIT`

```bash
#!/usr/bin/env bash
set -euo pipefail

WORK_DIR=$(mktemp -d "${TMPDIR:-/tmp}/build.XXXXXXXXXX")
trap 'rm -rf "$WORK_DIR"' EXIT

echo "工作目录: $WORK_DIR"
```

**实战示例：安全的中间文件处理**

```bash
#!/usr/bin/env bash
set -euo pipefail

WORK_DIR=$(mktemp -d)
trap 'rm -rf "$WORK_DIR"' EXIT

input_file="${1:?用法: $0 <input_file>}"

# 第一步：提取数据到临时文件
grep "ERROR" "$input_file" > "$WORK_DIR/errors.txt" || true

# 第二步：排序去重
sort -u "$WORK_DIR/errors.txt" > "$WORK_DIR/errors_unique.txt"

# 第三步：统计并输出结果到 stdout
total=$(wc -l < "$WORK_DIR/errors_unique.txt")
echo "共发现 $total 个不重复的错误:"
cat "$WORK_DIR/errors_unique.txt"

# 脚本结束时 $WORK_DIR 自动清理
```

## 7 超时与重试

### 7.1 timeout 命令

**`timeout`** 命令为其他命令设置最大执行时间，超时后发送终止信号。

```bash
# 限制 curl 最多执行 10 秒
timeout 10 curl -s "http://slow-api.example.com/data"

# 检查是否超时（退出码 124 表示超时）
if ! timeout 5 ping -c 3 example.com > /dev/null 2>&1; then
    echo "ping 超时或失败"
fi

# -s 参数指定信号，默认 SIGTERM
# --kill-after 在 SIGTERM 后若进程仍存活，再发 SIGKILL
timeout --kill-after=5 30 long_running_task
```

> **提示**：macOS 上需要安装 GNU coreutils（`brew install coreutils`），使用 `gtimeout` 代替 `timeout`。

### 7.2 指数退避重试

网络请求失败后立即重试往往无效，**指数退避（Exponential Backoff）** 逐步增加等待间隔，给服务恢复留出时间。

```bash
retry_with_backoff() {
    local max_attempts=$1
    local base_delay=$2
    shift 2
    local cmd=("$@")

    local attempt=1
    local delay="$base_delay"

    while [ "$attempt" -le "$max_attempts" ]; do
        if "${cmd[@]}"; then
            return 0
        fi

        if [ "$attempt" -eq "$max_attempts" ]; then
            break
        fi

        echo "WARN: 第 ${attempt}/${max_attempts} 次失败，${delay}s 后重试..." >&2
        sleep "$delay"
        # 指数退避：1s → 2s → 4s → 8s ...
        delay=$((delay * 2))
        ((attempt++))
    done

    echo "ERROR: ${cmd[*]} 在 ${max_attempts} 次尝试后仍然失败" >&2
    return 1
}

# 使用：最多 5 次，初始间隔 1 秒
retry_with_backoff 5 1 curl -sf "http://api.example.com/health"
```

退避时间线示意：

```
尝试 1  ──失败──  等 1s
尝试 2  ──失败──  等 2s
尝试 3  ──失败──  等 4s
尝试 4  ──失败──  等 8s
尝试 5  ──失败──  放弃
```

### 7.3 实战：健康检查脚本

等待服务启动就绪后再执行后续操作，是部署脚本中的常见需求。

```bash
#!/usr/bin/env bash
set -euo pipefail

SERVICE_URL="${1:?用法: $0 <service_url>}"
MAX_WAIT="${2:-60}"
INTERVAL="${3:-2}"

die() { echo "FATAL: $*" >&2; exit 1; }

wait_for_service() {
    local url="$1"
    local max_wait="$2"
    local interval="$3"
    local elapsed=0

    echo "等待服务就绪: $url (最长 ${max_wait}s)"

    while [ "$elapsed" -lt "$max_wait" ]; do
        if curl -sf "$url" > /dev/null 2>&1; then
            echo "服务已就绪 (耗时 ${elapsed}s)"
            return 0
        fi
        echo "  第 $((elapsed / interval + 1)) 次检查: 未就绪，${interval}s 后重试..."
        sleep "$interval"
        elapsed=$((elapsed + interval))
    done

    return 1
}

if ! wait_for_service "$SERVICE_URL" "$MAX_WAIT" "$INTERVAL"; then
    die "服务在 ${MAX_WAIT}s 内未就绪: $SERVICE_URL"
fi

echo "继续执行部署任务..."
```

运行方式：

```bash
# 等待本地服务启动，最长 30 秒，每 2 秒检查一次
./healthcheck.sh http://localhost:8080/health 30 2
```

## 8 小结

1. **退出状态码是 Shell 错误处理的基础**。始终检查 `$?` 或使用 `set -e`，不要让错误静默通过。

2. **`set -euo pipefail` 是每个脚本的必备开头**。这三个选项分别防止：忽略失败命令、使用未定义变量、管道中间环节失败被掩盖。

3. **`trap EXIT` 保证清理逻辑一定执行**，无论脚本以何种方式退出。用于清理临时文件、释放锁、关闭连接。

4. **`trap ERR` 结合 `$LINENO` 和 `$BASH_COMMAND`** 可以自动输出错误发生的位置和原因，极大降低排错成本。

5. **根据场景选择错误处理模式**：简单命令用 `||`，复杂逻辑用 `if`，统一退出用 `die`，暂时性故障用 `retry`。

6. **调试首选 `set -x` + 自定义 `PS4`**，配合 `shellcheck` 做静态分析，能发现绝大多数常见问题。

7. **始终用 `mktemp` 创建临时文件**，配合 `trap EXIT` 自动清理。永远不要硬编码临时文件路径。

8. **超时和重试是生产脚本的必备能力**。用 `timeout` 防止命令无限阻塞，用指数退避策略进行智能重试。
