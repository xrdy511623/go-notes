## 1 函数定义与调用

### 1.1 两种定义语法

Bash 支持两种函数定义语法：

```bash
# 语法一：使用 function 关键字（Bash 扩展）
function greet {
    echo "Hello, $1"
}

# 语法二：POSIX 兼容语法（推荐）
greet() {
    echo "Hello, $1"
}
```

| 语法 | POSIX 兼容 | 可移植性 | 推荐度 |
|------|-----------|---------|--------|
| `function name { }` | ❌ | 仅 Bash/Ksh | 一般 |
| `name() { }` | ✅ | 所有 POSIX Shell | **推荐** |

> **提示**：始终使用 `name() { }` 语法。这样你的脚本可以在 `dash`、`sh`、`zsh` 等 Shell 中运行，而不仅限于 Bash。

### 1.2 调用函数

调用函数和执行普通命令完全一致——直接写函数名，后面跟参数：

```bash
greet() {
    echo "Hello, $1"
}

# 调用：函数名 参数1 参数2 ...
greet "Alice"
# 输出: Hello, Alice
```

函数调用不需要加括号，这和 Python/JavaScript 等语言不同。加括号反而是语法错误。

### 1.3 定义顺序

Shell 按顺序逐行解析脚本。**函数定义必须出现在调用之前**，否则会报 `command not found`：

```bash
# ❌ 错误：调用在定义之前
greet "Alice"

greet() {
    echo "Hello, $1"
}
# 报错: greet: command not found
```

```bash
# ✅ 正确：先定义，后调用
greet() {
    echo "Hello, $1"
}

greet "Alice"
```

### 1.4 删除函数

使用 `unset -f` 可以删除已定义的函数：

```bash
greet() {
    echo "Hello"
}

greet
# 输出: Hello

unset -f greet

greet
# 报错: greet: command not found
```

> **提示**：`unset -f` 删除函数，`unset -v` 删除变量。单独使用 `unset name` 时，如果同名变量和函数都存在，优先删除变量。

## 2 参数传递

### 2.1 位置参数

函数内部使用 `$1`、`$2`、`$@` 等**位置参数**（Positional Parameters）获取传入的参数。语义与脚本级别的位置参数相同，但作用域独立——函数内的 `$1` 不会覆盖脚本的 `$1`。

| 变量 | 含义 |
|------|------|
| `$0` | 脚本名（不是函数名） |
| `$1` ~ `$9` | 第 1 ~ 9 个参数 |
| `${10}` | 第 10 个及以后的参数需要花括号 |
| `$#` | 参数个数 |
| `$@` | 所有参数（各自独立引用） |
| `$*` | 所有参数（合并为一个字符串） |

```bash
show_args() {
    echo "函数收到 $# 个参数"
    echo "第一个: $1"
    echo "第二个: $2"
    echo "全部: $@"
}

show_args "apple" "banana" "cherry"
# 函数收到 3 个参数
# 第一个: apple
# 第二个: banana
# 全部: apple banana cherry
```

> ⚠️ **注意**：函数内的 `$0` 仍然是脚本文件名，不是函数名。要获取当前函数名，使用 `${FUNCNAME[0]}`。

### 2.2 shift 在函数内使用

`shift` 在函数内只影响函数的参数列表，不会动脚本的参数：

```bash
process_flags() {
    while [[ $# -gt 0 ]]; do
        case "$1" in
            -v) echo "verbose 模式开启" ;;
            -d) echo "debug 模式开启" ;;
            *)  echo "未知选项: $1" ;;
        esac
        shift  # 弹出 $1，$2 变成新的 $1
    done
}

process_flags -v -d -x
# verbose 模式开启
# debug 模式开启
# 未知选项: -x
```

### 2.3 实战：格式化多参数输出

```bash
log_entry() {
    local level="$1"
    shift  # 剩余参数作为消息内容
    local timestamp
    timestamp=$(date '+%Y-%m-%d %H:%M:%S')
    printf "[%s] %-5s %s\n" "$timestamp" "$level" "$*"
}

log_entry "INFO"  "服务启动成功"
log_entry "ERROR" "连接数据库失败" "host=10.0.0.1" "port=3306"
# [2026-03-09 10:30:00] INFO  服务启动成功
# [2026-03-09 10:30:00] ERROR 连接数据库失败 host=10.0.0.1 port=3306
```

## 3 返回值

Shell 函数的"返回值"有三种方式，各有适用场景。

### 3.1 return 退出码

**`return`** 设置函数的退出状态码，取值范围 **0–255**，调用方用 `$?` 获取。

```bash
is_root() {
    [[ $(id -u) -eq 0 ]]
    return $?  # 也可省略，默认返回最后一条命令的退出码
}

if is_root; then
    echo "当前是 root 用户"
else
    echo "当前不是 root 用户"
fi
```

`return` 与 `exit` 的关键区别：

| 命令 | 作用 | 影响范围 |
|------|------|---------|
| `return N` | 结束函数，设置退出码 | 仅当前函数 |
| `exit N` | 结束整个脚本，设置退出码 | 整个脚本进程 |

```bash
wrong_example() {
    exit 1  # ❌ 这会终止整个脚本，不仅仅是函数
}

right_example() {
    return 1  # ✅ 只退出函数
}
```

> ⚠️ **注意**：`return` 只能返回整数且不超过 255。如果你需要返回字符串、路径或计算结果，请使用 stdout 捕获。

### 3.2 通过 stdout 返回数据

这是函数返回字符串或复杂数据的**标准方式**——函数向 stdout 输出，调用方用 `$(...)` 捕获：

```bash
get_hostname() {
    hostname -f
}

# 捕获函数输出到变量
my_host=$(get_hostname)
echo "主机名: $my_host"
```

实战：返回计算结果。

```bash
calc_disk_usage() {
    local path="${1:-.}"
    du -sh "$path" 2>/dev/null | awk '{print $1}'
}

usage=$(calc_disk_usage /var/log)
echo "/var/log 占用: $usage"
```

实战：返回 JSON 字符串。

```bash
build_json() {
    local name="$1"
    local status="$2"
    printf '{"name":"%s","status":"%s","timestamp":"%s"}' \
        "$name" "$status" "$(date -u +%FT%TZ)"
}

json=$(build_json "web-api" "healthy")
echo "$json"
# {"name":"web-api","status":"healthy","timestamp":"2026-03-09T02:30:00Z"}
```

> ⚠️ **注意**：使用 stdout 返回值时，函数内不要混入 `echo` 调试信息，否则调试信息会被一起捕获。调试信息应写入 stderr：`echo "debug info" >&2`。

### 3.3 通过全局变量返回

函数直接修改全局变量，调用方读取：

```bash
split_path() {
    RESULT_DIR=$(dirname "$1")
    RESULT_FILE=$(basename "$1")
}

split_path "/var/log/syslog"
echo "目录: $RESULT_DIR"   # /var/log
echo "文件: $RESULT_FILE"  # syslog
```

这种方式简单直接，但**破坏封装性**——函数和调用方之间通过约定的全局变量名耦合。

适用场景：脚本行数 < 100、只有你一个人维护、全局变量名有明确约定（如统一前缀 `RESULT_`）。规模稍大的脚本应优先使用 stdout 捕获。

## 4 变量作用域

### 4.1 默认全局的陷阱

Bash 函数内定义的变量**默认是全局的**。这是最常见的 Shell 编程陷阱之一：

```bash
set_value() {
    count=42  # 没有 local，这是全局变量
}

count=0
set_value
echo "$count"
# 输出: 42（被函数意外修改了！）
```

当多个函数使用相同的变量名（如 `i`、`tmp`、`result`），就会互相覆盖产生难以排查的 bug。

### 4.2 local 关键字

**`local`** 将变量限制在函数作用域内：

```bash
set_value() {
    local count=42  # 只在函数内可见
    echo "函数内: $count"
}

count=0
set_value
echo "函数外: $count"
# 函数内: 42
# 函数外: 0（未被修改）
```

`local` 支持与普通赋值相同的语法：

```bash
my_func() {
    local name="Alice"          # 赋初始值
    local -r PI=3.14            # 只读局部变量
    local -i num=10             # 整数类型
    local -a arr=(1 2 3)        # 数组
}
```

> ⚠️ **注意**：`local` 只能在函数内部使用，在函数外使用会报错。

### 4.3 declare 在函数内的行为

`declare` 在函数内部的效果等同于 `local`——声明的变量自动成为局部变量：

```bash
my_func() {
    declare msg="hello"  # 等同于 local msg="hello"
    echo "$msg"
}

my_func
echo "${msg:-未定义}"
# hello
# 未定义
```

在函数外部，`declare` 声明的是全局变量。这个行为差异需要注意。

### 4.4 最佳实践

**函数内所有变量都用 `local` 声明**，只有明确需要对外暴露的才用全局变量。

```bash
# ✅ 推荐写法
process_file() {
    local input_file="$1"
    local line_count=0
    local line

    while IFS= read -r line; do
        (( line_count++ ))
    done < "$input_file"

    echo "$line_count"
}

# ❌ 不推荐：变量全部暴露到全局
process_file_bad() {
    input_file="$1"
    line_count=0
    while IFS= read -r line; do
        (( line_count++ ))
    done < "$input_file"
    echo "$line_count"
}
```

## 5 递归函数

### 5.1 阶乘计算

Bash 支持函数递归调用。经典的阶乘示例：

```bash
factorial() {
    local n=$1
    if (( n <= 1 )); then
        echo 1
    else
        local sub
        sub=$(factorial $(( n - 1 )))
        echo $(( n * sub ))
    fi
}

result=$(factorial 5)
echo "5! = $result"
# 5! = 120
```

> **提示**：由于每次递归都会创建子 Shell（`$(...)` 命令替换），性能远不如循环。阶乘这类计算在实际脚本中应优先用循环实现，这里仅演示递归机制。

### 5.2 递归遍历目录树

递归真正有用的场景——遍历目录树：

```bash
walk_tree() {
    local dir="$1"
    local indent="${2:-}"
    local entry

    for entry in "$dir"/*; do
        [[ -e "$entry" ]] || continue  # 跳过空目录的 glob 结果
        local name
        name=$(basename "$entry")

        if [[ -d "$entry" ]]; then
            echo "${indent}📁 $name/"
            walk_tree "$entry" "  $indent"  # 递归进入子目录
        else
            echo "${indent}📄 $name"
        fi
    done
}

walk_tree /etc/nginx
# 📁 conf.d/
#   📄 default.conf
# 📄 nginx.conf
# 📄 mime.types
```

### 5.3 递归深度限制

Bash 提供 **`FUNCNEST`** 变量控制最大递归深度，防止无限递归耗尽资源：

```bash
FUNCNEST=50  # 限制最多 50 层嵌套调用

infinite_loop() {
    infinite_loop
}

infinite_loop
# 报错: infinite_loop: maximum function nesting level exceeded (50)
```

`FUNCNEST` 默认未设置（不限制）。在生产脚本中建议设置一个合理的值作为安全网。

## 6 函数库模式

当脚本超过几百行，就需要将函数拆分到独立文件中形成**函数库**（Library）。

### 6.1 source 加载

**`source`**（或等效的 `.`）命令在当前 Shell 中执行指定文件，文件中的函数和变量都进入当前作用域：

```bash
# 两种写法完全等价
source ./lib/logging.sh
. ./lib/logging.sh
```

被 source 的文件不需要可执行权限，也不需要 shebang 行。

```bash
# lib/math.sh —— 一个简单的函数库
add() { echo $(( $1 + $2 )); }
sub() { echo $(( $1 - $2 )); }
mul() { echo $(( $1 * $2 )); }
```

```bash
# main.sh
source ./lib/math.sh

result=$(add 3 5)
echo "3 + 5 = $result"
# 3 + 5 = 8
```

> ⚠️ **注意**：`source` 是在当前 Shell 进程中执行文件内容。如果被 source 的文件里有 `exit`，会导致当前脚本也退出。函数库中应使用 `return` 代替 `exit`。

### 6.2 函数库的组织结构

中等规模的 Shell 项目推荐如下目录结构：

```
project/
├── bin/
│   └── deploy.sh          # 主脚本（入口）
├── lib/
│   ├── logging.sh         # 日志函数库
│   ├── validation.sh      # 参数验证函数库
│   └── network.sh         # 网络工具函数库
└── etc/
    └── config.sh          # 配置变量（常量）
```

```
调用关系:

deploy.sh
    ├── source etc/config.sh      # 加载配置
    ├── source lib/logging.sh     # 加载日志函数
    ├── source lib/validation.sh  # 加载验证函数
    └── source lib/network.sh     # 加载网络函数
            └── source lib/logging.sh  # network.sh 内部也用日志
```

### 6.3 防止重复加载

当多个库文件相互依赖时，同一个文件可能被 source 多次。使用**标记变量**（类似 C 头文件的 include guard）防止重复加载：

```bash
# lib/logging.sh
[[ -n "${_LOGGING_SH_LOADED:-}" ]] && return 0
_LOGGING_SH_LOADED=1

log_info()  { printf "[INFO]  %s\n" "$*"; }
log_warn()  { printf "[WARN]  %s\n" "$*"; }
log_error() { printf "[ERROR] %s\n" "$*" >&2; }
```

原理：第一次 source 时 `_LOGGING_SH_LOADED` 未定义，条件不成立，继续执行。后续再次 source 时变量已存在，`return 0` 直接返回。

### 6.4 获取脚本自身路径

在 source 链中，相对路径容易出错。用以下模式获取脚本自身所在目录，然后基于绝对路径加载库文件：

```bash
SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)
```

**`BASH_SOURCE[0]`** 与 **`$0`** 的区别：

| 变量 | 含义 |
|------|------|
| `$0` | 当前执行的脚本名（被 source 时是父脚本名） |
| `${BASH_SOURCE[0]}` | 当前文件名（即使被 source 也指向自身） |

```bash
# lib/logging.sh
_LIB_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)
source "$_LIB_DIR/utils.sh"  # 可靠地 source 同目录下的文件
```

```bash
# bin/deploy.sh
SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)
PROJECT_DIR=$(dirname "$SCRIPT_DIR")

source "$PROJECT_DIR/etc/config.sh"
source "$PROJECT_DIR/lib/logging.sh"
source "$PROJECT_DIR/lib/network.sh"
```

无论从哪个目录执行 `deploy.sh`，路径都是正确的。

## 7 高阶技巧

### 7.1 函数作为参数

Shell 没有一等函数的概念，但可以将**函数名作为字符串传递**，然后用 `"$func" args...` 调用：

```bash
retry() {
    local max_attempts=$1
    local delay=$2
    local cmd=$3
    shift 3  # 剩余参数传给被调用的命令

    local attempt=1
    while (( attempt <= max_attempts )); do
        echo "尝试第 $attempt 次..."
        if "$cmd" "$@"; then
            echo "成功"
            return 0
        fi
        (( attempt++ ))
        sleep "$delay"
    done

    echo "失败：已重试 $max_attempts 次" >&2
    return 1
}

# 定义一个可能失败的函数
check_service() {
    curl -sf "http://$1/health" > /dev/null
}

# 传递函数名和参数：重试 3 次，每次间隔 2 秒
retry 3 2 check_service "localhost:8080"
```

这个 `retry` 函数可以包裹任意命令或函数，是生产脚本中非常实用的模式。

### 7.2 函数在管道中

函数和普通命令一样，可以接收 stdin、输出到 stdout，因此可以直接参与管道：

```bash
to_upper() {
    while IFS= read -r line; do
        echo "${line^^}"
    done
}

extract_errors() {
    while IFS= read -r line; do
        [[ "$line" == *"ERROR"* ]] && echo "$line"
    done
}

# 组合使用：提取错误行并转大写
cat /var/log/app.log | extract_errors | to_upper
```

> **提示**：管道中每个部分在独立的子 Shell 中执行。函数在管道中修改的变量不会影响父 Shell。这也是 `while read` 管道陷阱的根源。

### 7.3 FUNCNAME 和 BASH_LINENO 数组

Bash 维护两个内置数组，记录完整的**调用栈**（Call Stack）信息：

| 数组 | 含义 |
|------|------|
| `FUNCNAME` | 函数调用栈，`[0]` 是当前函数，`[1]` 是调用者 |
| `BASH_LINENO` | 对应调用发生的行号 |
| `BASH_SOURCE` | 对应调用发生的文件名 |

实战：带调用栈信息的 `die` 函数，用于错误追踪和日志记录：

```bash
die() {
    local msg="$1"
    local code="${2:-1}"

    echo "====== FATAL ERROR ======" >&2
    echo "消息: $msg" >&2
    echo "退出码: $code" >&2
    echo "调用栈:" >&2

    local i
    for (( i=1; i < ${#FUNCNAME[@]}; i++ )); do
        printf "  [%d] %s() at %s:%d\n" \
            "$i" \
            "${FUNCNAME[$i]}" \
            "${BASH_SOURCE[$i]}" \
            "${BASH_LINENO[$i-1]}" >&2
    done

    echo "=========================" >&2
    exit "$code"
}

# 使用示例
connect_db() {
    # 模拟连接失败
    die "无法连接数据库: host=10.0.0.1 port=3306"
}

start_app() {
    connect_db
}

start_app
# ====== FATAL ERROR ======
# 消息: 无法连接数据库: host=10.0.0.1 port=3306
# 退出码: 1
# 调用栈:
#   [1] connect_db() at ./app.sh:25
#   [2] start_app() at ./app.sh:29
#   [3] main() at ./app.sh:32
# =========================
```

## 8 脚本组织最佳实践

### 8.1 脚本结构模板

一个组织良好的 Bash 脚本应遵循固定的结构顺序：

```bash
#!/usr/bin/env bash
#
# 脚本名称: deploy.sh
# 功能描述: 自动部署应用到目标服务器
# 用法: ./deploy.sh [-e env] [-v] <version>

# ── 1. 安全选项 ──
set -euo pipefail

# ── 2. 常量定义 ──
readonly VERSION="1.0.0"
readonly DEFAULT_ENV="staging"
readonly LOG_FILE="/var/log/deploy.log"

# ── 3. 获取脚本路径 & 加载库 ──
SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)
source "$SCRIPT_DIR/../lib/logging.sh"
source "$SCRIPT_DIR/../lib/validation.sh"

# ── 4. 全局变量（可被参数覆盖的状态） ──
ENVIRONMENT="$DEFAULT_ENV"
VERBOSE=false

# ── 5. 函数定义 ──
usage() {
    cat <<EOF
用法: $(basename "$0") [-e env] [-v] <version>

选项:
  -e ENV    目标环境 (默认: $DEFAULT_ENV)
  -v        详细输出
  -h        显示帮助
EOF
    exit 0
}

parse_args() {
    while getopts ":e:vh" opt; do
        case "$opt" in
            e) ENVIRONMENT="$OPTARG" ;;
            v) VERBOSE=true ;;
            h) usage ;;
            :) die "选项 -$OPTARG 需要参数" ;;
            *) die "未知选项: -$OPTARG" ;;
        esac
    done
    shift $((OPTIND - 1))

    [[ $# -ge 1 ]] || die "缺少 version 参数"
    APP_VERSION="$1"
}

deploy() {
    log_info "开始部署 v${APP_VERSION} 到 ${ENVIRONMENT}"
    # ... 实际部署逻辑 ...
    log_info "部署完成"
}

# ── 6. 主函数 ──
main() {
    parse_args "$@"
    validate_environment "$ENVIRONMENT"
    deploy
}

# ── 7. 入口 ──
main "$@"
```

### 8.2 main 函数模式

为什么推荐用 `main` 函数包裹脚本逻辑？

1. **延迟执行**：所有函数定义完成后才开始执行，避免定义顺序问题
2. **参数传递清晰**：`main "$@"` 明确将脚本参数传给入口函数
3. **可测试性**：可以 source 脚本获取函数定义而不触发执行（配合条件判断）

```bash
# 高级技巧：source 时不执行 main
main() {
    echo "脚本逻辑"
}

# 只有直接执行时才调用 main，被 source 时跳过
if [[ "${BASH_SOURCE[0]}" == "$0" ]]; then
    main "$@"
fi
```

这样其他脚本可以 `source` 你的脚本来复用函数，而不会触发 `main` 执行。

### 8.3 命名规范

| 类别 | 规范 | 示例 |
|------|------|------|
| 常量 | 大写 + 下划线 | `MAX_RETRY`、`DB_HOST` |
| 全局变量 | 大写 + 下划线 | `ENVIRONMENT`、`VERBOSE` |
| 局部变量 | 小写 + 下划线 | `local line_count=0` |
| 函数名 | 小写 + 下划线（snake_case） | `parse_args`、`check_service` |
| "私有"函数 | 下划线前缀 | `_internal_helper` |

### 8.4 Google Shell Style Guide 核心要点

Google 的 Shell 风格指南是业界最广泛参考的 Shell 编码规范，核心要点摘录：

1. **可执行脚本用 `#!/bin/bash`**，库文件不加 shebang
2. **所有可执行脚本必须有顶部注释**，说明功能和用法
3. **使用 `$(command)` 而不是反引号** `` `command` ``
4. **使用 `[[ ]]` 而不是 `[ ]`** 做条件判断
5. **引用所有变量**：`"$var"` 而不是 `$var`
6. **函数内用 `local` 声明变量**
7. **STDOUT 用于有用输出，STDERR 用于诊断信息**
8. **`main` 函数放在脚本最后**，紧接着 `main "$@"`
9. **超过 100 行的脚本应有函数**，不要写一长串顺序执行的命令
10. **缩进 2 个空格**，不用 Tab

> **提示**：完整指南参考 [Google Shell Style Guide](https://google.github.io/styleguide/shellguide.html)。

## 9 小结

1. **两种定义语法**中优先使用 `name() { }` 的 POSIX 兼容写法
2. 函数参数通过 `$1`、`$2`、`$@` 获取，与脚本参数语义相同但作用域独立
3. **`return` 只能返回 0–255 的退出码**；返回字符串数据用 `$(func)` 捕获 stdout
4. Bash 变量**默认全局**——函数内务必用 `local` 声明所有变量
5. **递归**可用但性能较差，注意通过 `FUNCNEST` 控制深度
6. 使用 **`source`** 加载函数库，用标记变量防止重复加载
7. 用 **`BASH_SOURCE[0]`** 获取脚本真实路径，确保相对路径可靠
8. 函数名可作为字符串传递，实现简单的高阶函数模式
9. 使用 **`FUNCNAME`** 数组获取调用栈，构建专业的错误追踪机制
10. 遵循「shebang → 选项 → 常量 → source → 函数 → main → main "$@"」的标准结构
