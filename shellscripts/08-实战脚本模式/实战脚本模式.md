## 1 生产级脚本模板

一个经过实践检验的脚本骨架，能让你在动手写逻辑之前就拥有错误处理、日志、帮助信息和清理机制。

### 1.1 完整骨架

```bash
#!/usr/bin/env bash
#
# deploy-app.sh — 应用部署脚本
# 版本: 1.0.0
# 用法: deploy-app.sh [-e env] [-v] [-h]
#
set -euo pipefail

# ── 全局常量 ──────────────────────────────────────────
readonly SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
readonly SCRIPT_NAME="$(basename "$0")"
readonly VERSION="1.0.0"

readonly LOG_FILE="/var/log/${SCRIPT_NAME%.sh}.log"
readonly LOCK_FILE="/tmp/${SCRIPT_NAME%.sh}.lock"

# ── 加载库文件 ────────────────────────────────────────
# shellcheck source=lib/logging.sh
source "${SCRIPT_DIR}/lib/logging.sh"

# ── 全局变量 ──────────────────────────────────────────
ENVIRONMENT="staging"
VERBOSE=false
TEMP_DIR=""

# ── usage ─────────────────────────────────────────────
usage() {
    cat <<EOF
用法: ${SCRIPT_NAME} [选项]

选项:
  -e ENV    部署环境 (staging|production), 默认: staging
  -v        详细输出
  -h        显示帮助

示例:
  ${SCRIPT_NAME} -e production
  ${SCRIPT_NAME} -v -e staging
EOF
}

# ── cleanup ───────────────────────────────────────────
cleanup() {
    local exit_code=$?
    if [[ -n "${TEMP_DIR}" && -d "${TEMP_DIR}" ]]; then
        rm -rf "${TEMP_DIR}"
        log_info "已清理临时目录: ${TEMP_DIR}"
    fi
    if [[ -f "${LOCK_FILE}" ]]; then
        rm -f "${LOCK_FILE}"
    fi
    exit "${exit_code}"
}
trap cleanup EXIT INT TERM

# ── 参数解析 ──────────────────────────────────────────
parse_args() {
    while getopts ":e:vh" opt; do
        case "${opt}" in
            e)
                ENVIRONMENT="${OPTARG}"
                if [[ "${ENVIRONMENT}" != "staging" && "${ENVIRONMENT}" != "production" ]]; then
                    log_error "无效环境: ${ENVIRONMENT}"
                    usage
                    exit 1
                fi
                ;;
            v) VERBOSE=true ;;
            h) usage; exit 0 ;;
            :) log_error "选项 -${OPTARG} 需要参数"; usage; exit 1 ;;
            *) log_error "未知选项: -${OPTARG}"; usage; exit 1 ;;
        esac
    done
    shift $((OPTIND - 1))
}

# ── 主逻辑 ────────────────────────────────────────────
main() {
    parse_args "$@"

    log_info "开始部署 [环境=${ENVIRONMENT}, 版本=${VERSION}]"

    TEMP_DIR="$(mktemp -d "/tmp/${SCRIPT_NAME%.sh}.XXXXXX")"
    log_info "临时目录: ${TEMP_DIR}"

    # ... 业务逻辑 ...

    log_info "部署完成"
}

main "$@"
```

### 1.2 结构解读

整个骨架按**从上到下、从声明到执行**的顺序排列：

| 区域 | 职责 | 设计理由 |
|---|---|---|
| Shebang + `set -euo pipefail` | 安全默认值 | 在任何逻辑执行前启用防御模式 |
| 全局常量 | `SCRIPT_DIR`, `SCRIPT_NAME`, `VERSION` | 用 `readonly` 防止意外修改；`SCRIPT_DIR` 保证 `source` 相对路径可靠 |
| `source` 库文件 | 加载共享函数 | 在常量定义之后、函数定义之前，确保库可用 |
| `usage()` | 帮助信息 | 放在最前面方便维护，`-h` 时直接调用 |
| `cleanup()` + `trap` | 资源回收 | 无论正常退出还是被 `kill`，都能清理临时文件和锁文件 |
| `parse_args()` | 参数处理 | 封装到函数中使 `main` 保持简洁 |
| `main()` | 业务入口 | 所有逻辑在 `main` 里执行，变量作用域更清晰 |
| `main "$@"` | 最末调用 | 确保所有函数和变量定义完毕后才执行 |

> **提示**: `${BASH_SOURCE[0]}` 比 `$0` 更可靠——当脚本被 `source` 加载时，`$0` 会变成父脚本的名字，而 `BASH_SOURCE[0]` 始终指向当前文件。

## 2 配置文件解析

### 2.1 Key=Value 配置文件

最常见的配置格式，形如 `.env` 或 `.conf`：

```
# 数据库配置
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=app
DB_PASS="s3cret"
```

**方式一：`source` 直接加载**——简单但危险。

```bash
# 配置文件中的任意命令都会被执行，存在注入风险
source /etc/app/db.conf
echo "${DB_HOST}"
```

> ⚠️ **注意**: 永远不要 `source` 不可信来源的配置文件。攻击者可以在文件中插入 `rm -rf /` 之类的命令。

**方式二：安全解析**——只提取 `KEY=VALUE`，忽略其它内容。

```bash
# 安全地读取 key=value 配置文件
# 参数: $1 = 配置文件路径
load_config() {
    local config_file="$1"

    if [[ ! -f "${config_file}" ]]; then
        echo "配置文件不存在: ${config_file}" >&2
        return 1
    fi

    while IFS='=' read -r key value; do
        # 跳过空行和注释
        [[ -z "${key}" || "${key}" =~ ^[[:space:]]*# ]] && continue

        # 去除首尾空白
        key="$(echo "${key}" | xargs)"
        value="$(echo "${value}" | xargs)"

        # 去除值两端的引号
        value="${value%\"}"
        value="${value#\"}"
        value="${value%\'}"
        value="${value#\'}"

        # 仅导出合法的变量名
        if [[ "${key}" =~ ^[a-zA-Z_][a-zA-Z0-9_]*$ ]]; then
            export "${key}=${value}"
        fi
    done < "${config_file}"
}
```

**实战示例**：读取数据库配置并连接。

```bash
load_config "/etc/app/db.conf"

mysql -h "${DB_HOST}" -P "${DB_PORT}" \
      -u "${DB_USER}" -p"${DB_PASS}" \
      -e "SELECT 1" || {
    echo "数据库连接失败" >&2
    exit 1
}
```

**从配置文件中读取单个值**的快捷方式：

```bash
# 从配置文件中取指定 key 的值
get_config() {
    local file="$1" key="$2"
    grep -E "^${key}=" "${file}" | head -1 | cut -d'=' -f2- | sed 's/^["'\''"]//;s/["'\''"]$//'
}

db_host="$(get_config /etc/app/db.conf DB_HOST)"
```

### 2.2 INI 格式解析

INI 文件通过 `[section]` 对配置分组：

```ini
[database]
host = 127.0.0.1
port = 3306

[redis]
host = 127.0.0.1
port = 6379
```

解析函数需要追踪当前 section：

```bash
# 解析 INI 文件，用 SECTION_KEY 格式导出变量
# 参数: $1 = INI 文件路径
parse_ini() {
    local ini_file="$1"
    local section=""

    while IFS='=' read -r key value; do
        # 跳过空行和注释
        [[ -z "${key}" || "${key}" =~ ^[[:space:]]*[#\;] ]] && continue

        # 匹配 section 行
        if [[ "${key}" =~ ^\[([a-zA-Z0-9_]+)\] ]]; then
            section="${BASH_REMATCH[1]}"
            continue
        fi

        key="$(echo "${key}" | xargs)"
        value="$(echo "${value}" | xargs)"

        if [[ -n "${section}" && -n "${key}" ]]; then
            local var_name="${section}_${key}"
            var_name="${var_name^^}"  # 转为大写
            export "${var_name}=${value}"
        fi
    done < "${ini_file}"
}
```

```bash
parse_ini config.ini

echo "${DATABASE_HOST}"  # 127.0.0.1
echo "${REDIS_PORT}"     # 6379
```

## 3 日志系统

### 3.1 带级别和颜色的日志函数

终端输出需要颜色帮助快速区分信息类型，但管道或文件重定向时必须去掉颜色转义码。

```
+-------------------------------------------+
|  终端 (tty)       |  管道 / 文件           |
|  带颜色 ANSI 码    |  纯文本               |
|  [INFO]  绿色     |  [INFO]  无色          |
|  [WARN]  黄色     |  [WARN]  无色          |
|  [ERROR] 红色     |  [ERROR] 无色          |
+-------------------------------------------+
```

颜色安全检测的关键是 `-t` 测试：

```bash
if [[ -t 2 ]]; then
    # stderr 连接到终端，可以使用颜色
    readonly COLOR_RED='\033[0;31m'
    readonly COLOR_GREEN='\033[0;32m'
    readonly COLOR_YELLOW='\033[0;33m'
    readonly COLOR_RESET='\033[0m'
else
    readonly COLOR_RED=''
    readonly COLOR_GREEN=''
    readonly COLOR_YELLOW=''
    readonly COLOR_RESET=''
fi
```

### 3.2 日志同时写终端与文件

日志函数的核心：写 stderr（给操作者看）+ 追加到文件（留审计记录）。

```bash
_log() {
    local level="$1" color="$2" message="$3"
    local timestamp
    timestamp="$(date '+%Y-%m-%d %H:%M:%S')"

    # 终端输出（带颜色）
    printf "${color}[%-5s]${COLOR_RESET} %s %s\n" \
        "${level}" "${timestamp}" "${message}" >&2

    # 文件输出（纯文本）
    printf "[%-5s] %s %s\n" \
        "${level}" "${timestamp}" "${message}" >> "${LOG_FILE}"
}

log_info()  { _log "INFO"  "${COLOR_GREEN}"  "$*"; }
log_warn()  { _log "WARN"  "${COLOR_YELLOW}" "$*"; }
log_error() { _log "ERROR" "${COLOR_RED}"    "$*"; }
```

### 3.3 日志轮转

生产环境的日志文件需要控制大小。简单实现：当文件超过阈值时重命名。

```bash
# 按大小轮转日志（超过 max_size 就归档）
rotate_log() {
    local log_file="$1"
    local max_size="${2:-10485760}"  # 默认 10MB
    local max_files="${3:-5}"

    [[ ! -f "${log_file}" ]] && return 0

    local file_size
    file_size="$(stat -f%z "${log_file}" 2>/dev/null || stat -c%s "${log_file}" 2>/dev/null)"

    if (( file_size > max_size )); then
        # 滚动旧文件：.4 → .5, .3 → .4, ...
        for (( i = max_files - 1; i >= 1; i-- )); do
            local src="${log_file}.$((i))"
            local dst="${log_file}.$((i + 1))"
            [[ -f "${src}" ]] && mv "${src}" "${dst}"
        done
        mv "${log_file}" "${log_file}.1"
        touch "${log_file}"
    fi
}
```

### 3.4 完整 logging.sh 库

将上述功能封装为可 `source` 的库文件：

```bash
#!/usr/bin/env bash
# lib/logging.sh — 通用日志库
# 依赖: 调用方须设置 LOG_FILE 变量

# 防止重复加载
[[ -n "${_LOGGING_SH_LOADED:-}" ]] && return 0
readonly _LOGGING_SH_LOADED=1

# ── 颜色检测 ──────────────────────────────────────────
if [[ -t 2 ]]; then
    readonly _CLR_RED='\033[0;31m'
    readonly _CLR_GREEN='\033[0;32m'
    readonly _CLR_YELLOW='\033[0;33m'
    readonly _CLR_RESET='\033[0m'
else
    readonly _CLR_RED='' _CLR_GREEN='' _CLR_YELLOW='' _CLR_RESET=''
fi

# ── 日志级别 ──────────────────────────────────────────
# DEBUG=0, INFO=1, WARN=2, ERROR=3
LOG_LEVEL="${LOG_LEVEL:-1}"

_should_log() {
    local level_num="$1"
    (( level_num >= LOG_LEVEL ))
}

_log() {
    local level_num="$1" level_name="$2" color="$3"
    shift 3
    local message="$*"

    _should_log "${level_num}" || return 0

    local ts
    ts="$(date '+%Y-%m-%d %H:%M:%S')"

    printf "${color}[%-5s]${_CLR_RESET} %s %s\n" \
        "${level_name}" "${ts}" "${message}" >&2

    if [[ -n "${LOG_FILE:-}" ]]; then
        printf "[%-5s] %s [%s] %s\n" \
            "${level_name}" "${ts}" "$$" "${message}" >> "${LOG_FILE}"
    fi
}

log_debug() { _log 0 "DEBUG" ""               "$@"; }
log_info()  { _log 1 "INFO"  "${_CLR_GREEN}"   "$@"; }
log_warn()  { _log 2 "WARN"  "${_CLR_YELLOW}"  "$@"; }
log_error() { _log 3 "ERROR" "${_CLR_RED}"     "$@"; }

# ── 日志轮转 ──────────────────────────────────────────
log_rotate() {
    local max_size="${1:-10485760}"
    local max_files="${2:-5}"
    [[ -z "${LOG_FILE:-}" || ! -f "${LOG_FILE}" ]] && return 0

    local size
    size="$(stat -f%z "${LOG_FILE}" 2>/dev/null || stat -c%s "${LOG_FILE}" 2>/dev/null)"

    if (( size > max_size )); then
        for (( i = max_files - 1; i >= 1; i-- )); do
            [[ -f "${LOG_FILE}.$i" ]] && mv "${LOG_FILE}.$i" "${LOG_FILE}.$((i+1))"
        done
        mv "${LOG_FILE}" "${LOG_FILE}.1"
        : > "${LOG_FILE}"
        log_info "日志已轮转"
    fi
}
```

> **提示**: 用 `_LOGGING_SH_LOADED` 守卫防止多次 `source` 时重复声明 `readonly` 变量导致报错。

## 4 并发控制

### 4.1 后台任务与 wait

`command &` 将命令放入后台，`wait` 等待其结束。

```bash
do_task() {
    local id="$1"
    sleep $(( RANDOM % 3 + 1 ))
    echo "任务 ${id} 完成"
}

pids=()
for i in {1..5}; do
    do_task "$i" &
    pids+=($!)
done

# 等待所有后台任务，逐个收集退出码
failed=0
for pid in "${pids[@]}"; do
    if ! wait "${pid}"; then
        (( failed++ ))
    fi
done

echo "失败任务数: ${failed}"
```

> **提示**: `$!` 保存最近一个后台进程的 PID；`wait $pid` 的返回值等于该进程的退出码。

### 4.2 并发数控制

无限制地启动后台任务会耗尽系统资源。使用**文件描述符（File Descriptor）+ `read`** 构造信号量：

```bash
# 并发检查多台服务器连通性，最多 max_jobs 个并发
check_servers() {
    local max_jobs="${1:-10}"
    shift
    local servers=("$@")

    # 创建 FIFO 信号量
    local fifo
    fifo="$(mktemp -u "/tmp/fifo.XXXXXX")"
    mkfifo "${fifo}"
    exec 6<>"${fifo}"   # 绑定到 fd 6
    rm -f "${fifo}"      # 删除文件名，fd 仍有效

    # 初始化令牌：向 fd 写入 max_jobs 个换行
    for (( i = 0; i < max_jobs; i++ )); do
        echo >&6
    done

    for server in "${servers[@]}"; do
        # 获取令牌（阻塞直到有空位）
        read -r -u 6

        {
            if ping -c1 -W2 "${server}" &>/dev/null; then
                echo "[OK]   ${server}"
            else
                echo "[FAIL] ${server}"
            fi
            # 归还令牌
            echo >&6
        } &
    done

    wait
    exec 6>&-  # 关闭 fd
}
```

工作原理：

```
fd 6 (FIFO)
┌──────────────────────────┐
│ token  token  token ...  │  初始 N 个令牌
└──────────────────────────┘
   ↑ read 取走一个           ↑ 任务完成时 echo 放回一个
```

**实战调用**：

```bash
servers=(
    "192.168.1.1" "192.168.1.2" "192.168.1.3"
    "10.0.0.1"    "10.0.0.2"    "10.0.0.3"
    # ... 可以有几十上百台
)

check_servers 10 "${servers[@]}"
```

**简单场景**可用 `xargs -P`：

```bash
cat server_list.txt | xargs -P 10 -I {} sh -c '
    if ping -c1 -W2 "{}" &>/dev/null; then
        echo "[OK]   {}"
    else
        echo "[FAIL] {}"
    fi
'
```

### 4.3 文件锁

`flock` 确保同一时刻只有一个脚本实例在运行——典型场景是 crontab 定时任务。

```bash
#!/usr/bin/env bash
set -euo pipefail

readonly LOCK_FILE="/tmp/my-cron-job.lock"

# 尝试获取排他锁，失败则退出
exec 200>"${LOCK_FILE}"
if ! flock -n 200; then
    echo "另一个实例正在运行，退出" >&2
    exit 0
fi

# 锁已获得，正常执行
echo "开始执行任务 ..."
sleep 30
echo "任务完成"
# 脚本退出时 fd 自动关闭，锁自动释放
```

也可以用 `flock` 命令行模式：

```bash
# crontab 中使用 —— 获取不到锁就跳过本次执行
* * * * * /usr/bin/flock -n /tmp/my-job.lock /opt/scripts/my-job.sh
```

| 方式 | 适用场景 | 特点 |
|---|---|---|
| `flock -n` (非阻塞) | cron 任务防重入 | 获取不到就立即退出 |
| `flock -w 10` (超时) | 需排队但不愿久等 | 等待 10 秒超时退出 |
| `flock` (阻塞) | 串行化必须执行的任务 | 无限等待直到获得锁 |

## 5 网络相关脚本

### 5.1 健康检查

**单个服务检查**：

```bash
# 检查 HTTP 服务是否健康
# 参数: $1=URL, $2=超时秒数(默认5), $3=重试次数(默认3)
check_http() {
    local url="$1"
    local timeout="${2:-5}"
    local retries="${3:-3}"

    for (( i = 1; i <= retries; i++ )); do
        local http_code
        http_code="$(curl -s -o /dev/null -w '%{http_code}' \
                         --connect-timeout "${timeout}" "${url}")" || true

        if [[ "${http_code}" =~ ^2 ]]; then
            return 0
        fi
        log_warn "第 ${i} 次检查失败: ${url} (HTTP ${http_code})"
        sleep 2
    done
    return 1
}

# 检查 TCP 端口是否可达
check_port() {
    local host="$1" port="$2" timeout="${3:-3}"
    if command -v nc &>/dev/null; then
        nc -z -w "${timeout}" "${host}" "${port}" 2>/dev/null
    else
        timeout "${timeout}" bash -c "echo >/dev/tcp/${host}/${port}" 2>/dev/null
    fi
}
```

**实战：批量服务健康检查脚本**

```bash
#!/usr/bin/env bash
set -euo pipefail

declare -A SERVICES=(
    ["api-gateway"]="http://api.internal:8080/health"
    ["user-service"]="http://user.internal:8081/health"
    ["order-service"]="http://order.internal:8082/health"
    ["mysql"]="tcp://db.internal:3306"
    ["redis"]="tcp://redis.internal:6379"
)

check_all_services() {
    local failed=0

    for name in "${!SERVICES[@]}"; do
        local endpoint="${SERVICES[${name}]}"

        if [[ "${endpoint}" == tcp://* ]]; then
            local hostport="${endpoint#tcp://}"
            local host="${hostport%%:*}"
            local port="${hostport##*:}"
            if check_port "${host}" "${port}"; then
                log_info "✓ ${name} (${host}:${port})"
            else
                log_error "✗ ${name} (${host}:${port})"
                (( failed++ ))
            fi
        else
            if check_http "${endpoint}"; then
                log_info "✓ ${name} (${endpoint})"
            else
                log_error "✗ ${name} (${endpoint})"
                (( failed++ ))
            fi
        fi
    done

    return "${failed}"
}

main() {
    log_info "开始健康检查 ..."
    if check_all_services; then
        log_info "所有服务正常"
    else

main
```

```bash
fetch_repo_info() {
```

```bash
# 发送钉钉/飞书告警通知
send_alert() {
    local webhook_url="$1"
    local title="$2"
    local content="$3"

    local payload
    payload="$(jq -n \
        --arg title "${title}" \
        --arg text "${content}" \
        '{msgtype: "text", text: {content: ($title + "\n" + $text)}}')"

    local http_code
    http_code="$(curl -s -o /dev/null -w '%{http_code}' \
        -H "Content-Type: application/json" \
        -d "${payload}" \
        "${webhook_url}")"

        log_error "告警发送失败 (HTTP ${http_code})"
        return 1
    fi
}
```

### 6.1 磁盘空间监控

```bash
#!/usr/bin/env bash
set -euo pipefail

readonly THRESHOLD="${1:-80}"  # 默认 80% 告警阈值
readonly ALERT_WEBHOOK="https://hooks.example.com/alert"

check_disk_usage() {
    local alert_needed=false

    # 解析 df 输出，跳过表头和 tmpfs
    while read -r filesystem size used avail pct mountpoint; do
        # 去掉百分号
        local usage="${pct%\%}"

        if (( usage >= THRESHOLD )); then
            log_error "磁盘告警: ${mountpoint} 使用率 ${usage}% (阈值 ${THRESHOLD}%)"
            alert_needed=true
        fi
    done < <(df -h --output=source,size,used,avail,pcent,target 2>/dev/null \
             | tail -n +2 \
             | grep -v tmpfs)

    # macOS 兼容: df 输出格式不同
    if [[ "$(uname)" == "Darwin" ]]; then
        while read -r line; do
            local usage mountpoint
            usage="$(echo "${line}" | awk '{print $(NF-1)}' | tr -d '%')"
            mountpoint="$(echo "${line}" | awk '{print $NF}')"

            if (( usage >= THRESHOLD )); then
                log_error "磁盘告警: ${mountpoint} 使用率 ${usage}%"
                alert_needed=true
            fi
        done < <(df -h | tail -n +2 | grep -v "^devfs")
    fi

    if "${alert_needed}"; then
        local hostname
        hostname="$(hostname)"
        send_alert "${ALERT_WEBHOOK}" \
            "[磁盘告警] ${hostname}" \
            "服务器 ${hostname} 磁盘使用率超过 ${THRESHOLD}%，请及时处理"
    fi
}

check_disk_usage
```

### 6.2 日志清理

```bash
#!/usr/bin/env bash
set -euo pipefail

# 清理指定目录中超过 N 天的日志文件
# 用法: clean_logs.sh /var/log/app 30
readonly LOG_DIR="${1:?用法: $0 <日志目录> [保留天数]}"
readonly KEEP_DAYS="${2:-30}"

clean_old_logs() {
    # 安全检查：目录必须存在且不是根目录
    if [[ ! -d "${LOG_DIR}" ]]; then
        echo "目录不存在: ${LOG_DIR}" >&2
        exit 1
    fi

    local real_path
    real_path="$(cd "${LOG_DIR}" && pwd)"
    if [[ "${real_path}" == "/" ]]; then
        echo "拒绝操作根目录" >&2
        exit 1
    fi

    echo "清理目录: ${real_path}"
    echo "保留天数: ${KEEP_DAYS}"

    # 删除旧日志文件
    local count=0
    while IFS= read -r -d '' file; do
        echo "删除: ${file}"
        rm -f "${file}"
        (( count++ ))
    done < <(find "${real_path}" -maxdepth 2 \
                  -type f \( -name "*.log" -o -name "*.log.*" \) \
                  -mtime "+${KEEP_DAYS}" \
                  -print0)

    echo "共删除 ${count} 个文件"

    # 压缩大于 100MB 的活跃日志
    while IFS= read -r -d '' file; do
        if [[ ! "${file}" =~ \.gz$ ]]; then
            echo "压缩: ${file}"
            gzip "${file}"
        fi
    done < <(find "${real_path}" -maxdepth 2 \
                  -type f -name "*.log.*" \
                  -size +100M \
                  -print0)
}

clean_old_logs
```

> ⚠️ **注意**: 始终检查目标路径不是 `/`，避免变量为空时 `rm -rf /` 灾难。`find` 配合 `-maxdepth` 限制递归深度也是一层保护。

### 6.3 备份脚本

```bash
#!/usr/bin/env bash
set -euo pipefail

# ── 配置 ─────────────────────────────────────────────
readonly BACKUP_DIR="/data/backups"
readonly KEEP_COPIES=7
readonly DATE_TAG="$(date '+%Y%m%d_%H%M%S')"

readonly DB_HOST="127.0.0.1"
readonly DB_USER="backup"
readonly DB_PASS="secret"
readonly DB_NAME="myapp"

readonly APP_DATA_DIR="/opt/app/data"

# ── 数据库备份 ───────────────────────────────────────
backup_database() {
    local dump_file="${BACKUP_DIR}/db_${DB_NAME}_${DATE_TAG}.sql.gz"

    log_info "备份数据库: ${DB_NAME}"

    mysqldump -h "${DB_HOST}" -u "${DB_USER}" -p"${DB_PASS}" \
        --single-transaction \
        --routines \
        --triggers \
        "${DB_NAME}" | gzip > "${dump_file}"

    local size
    size="$(du -h "${dump_file}" | cut -f1)"
    log_info "数据库备份完成: ${dump_file} (${size})"
}

# ── 文件备份 ─────────────────────────────────────────
backup_files() {
    local tar_file="${BACKUP_DIR}/files_${DATE_TAG}.tar.gz"

    log_info "备份应用数据: ${APP_DATA_DIR}"

    tar -czf "${tar_file}" \
        --exclude='*.tmp' \
        --exclude='cache/*' \
        -C "$(dirname "${APP_DATA_DIR}")" \
        "$(basename "${APP_DATA_DIR}")"

    local size
    size="$(du -h "${tar_file}" | cut -f1)"
    log_info "文件备份完成: ${tar_file} (${size})"
}

# ── 清理旧备份 ───────────────────────────────────────
prune_old_backups() {
    log_info "保留最近 ${KEEP_COPIES} 份备份"

    for prefix in "db_${DB_NAME}" "files"; do
        local files
        mapfile -t files < <(ls -1t "${BACKUP_DIR}/${prefix}_"*.gz 2>/dev/null)

        if (( ${#files[@]} > KEEP_COPIES )); then
            for (( i = KEEP_COPIES; i < ${#files[@]}; i++ )); do
                log_info "删除旧备份: ${files[i]}"
                rm -f "${files[i]}"
            done
        fi
    done
}

main() {
    mkdir -p "${BACKUP_DIR}"
    backup_database
    backup_files
    prune_old_backups
    log_info "全部备份任务完成"
}

main
```

**保留策略**的核心逻辑：`ls -1t` 按时间倒序列出同前缀的备份文件，保留前 N 个，删除其余。

## 7 部署脚本

### 7.1 应用发布

**符号链接方案（Symlink Deploy）**——在部署新版本的同时保留回滚能力：

```
/opt/app/
├── releases/
│   ├── 20260308_120000/    ← 旧版本（保留）
│   └── 20260309_100000/    ← 新版本
├── current -> releases/20260309_100000   ← 符号链接
└── shared/                 ← 共享的日志、上传文件等
```

**完整部署脚本**：

```bash
#!/usr/bin/env bash
set -euo pipefail

readonly APP_NAME="myapp"
readonly DEPLOY_BASE="/opt/${APP_NAME}"
readonly RELEASES_DIR="${DEPLOY_BASE}/releases"
readonly SHARED_DIR="${DEPLOY_BASE}/shared"
readonly CURRENT_LINK="${DEPLOY_BASE}/current"

readonly GIT_REPO="git@github.com:company/${APP_NAME}.git"
readonly BRANCH="${1:-main}"
readonly RELEASE_TAG="$(date '+%Y%m%d_%H%M%S')"
readonly RELEASE_DIR="${RELEASES_DIR}/${RELEASE_TAG}"

readonly KEEP_RELEASES=5
readonly HEALTH_URL="http://localhost:8080/health"
readonly HEALTH_TIMEOUT=30

log_info()  { printf "[INFO]  %s %s\n" "$(date '+%H:%M:%S')" "$*" >&2; }
log_error() { printf "[ERROR] %s %s\n" "$(date '+%H:%M:%S')" "$*" >&2; }

# ── Step 1: 拉取代码 ─────────────────────────────────
fetch_code() {
    log_info "拉取代码 (branch: ${BRANCH})"
    git clone --depth 1 --branch "${BRANCH}" "${GIT_REPO}" "${RELEASE_DIR}"
}

# ── Step 2: 构建 ─────────────────────────────────────
build() {
    log_info "构建应用"
    cd "${RELEASE_DIR}"
    go build -o "${APP_NAME}" ./cmd/server
    cd -
}

# ── Step 3: 链接共享资源 ─────────────────────────────
link_shared() {
    ln -sfn "${SHARED_DIR}/logs" "${RELEASE_DIR}/logs"
    ln -sfn "${SHARED_DIR}/.env" "${RELEASE_DIR}/.env"
}

# ── Step 4: 停旧 → 切链接 → 起新 ────────────────────
switch_version() {
    log_info "停止旧服务"
    if [[ -L "${CURRENT_LINK}" ]]; then
        local old_pid_file="${CURRENT_LINK}/${APP_NAME}.pid"
        if [[ -f "${old_pid_file}" ]]; then
            local old_pid
            old_pid="$(cat "${old_pid_file}")"
            kill "${old_pid}" 2>/dev/null && sleep 2 || true
        fi
    fi

    log_info "切换版本: ${RELEASE_TAG}"
    ln -sfn "${RELEASE_DIR}" "${CURRENT_LINK}"

    log_info "启动新服务"
    cd "${CURRENT_LINK}"
    nohup "./${APP_NAME}" >> logs/stdout.log 2>&1 &
    echo $! > "${APP_NAME}.pid"
    cd -
}

# ── Step 5: 健康检查 ─────────────────────────────────
wait_healthy() {
    log_info "等待服务就绪 (最长 ${HEALTH_TIMEOUT}s)"
    for (( i = 1; i <= HEALTH_TIMEOUT; i++ )); do
        if curl -sf "${HEALTH_URL}" &>/dev/null; then
            log_info "服务已就绪 (${i}s)"
            return 0
        fi
        sleep 1
    done
    log_error "健康检查超时"
    return 1
}

# ── Step 6: 清理旧版本 ──────────────────────────────
prune_releases() {
    local releases
    mapfile -t releases < <(ls -1t "${RELEASES_DIR}")

    if (( ${#releases[@]} > KEEP_RELEASES )); then
        for (( i = KEEP_RELEASES; i < ${#releases[@]}; i++ )); do
            log_info "删除旧版本: ${releases[i]}"
            rm -rf "${RELEASES_DIR:?}/${releases[i]}"
        done
    fi
}

# ── 回滚 ─────────────────────────────────────────────
rollback() {
    local releases
    mapfile -t releases < <(ls -1t "${RELEASES_DIR}")

    if (( ${#releases[@]} < 2 )); then
        log_error "无可用的回滚版本"
        return 1
    fi

    local prev="${releases[1]}"
    log_info "回滚到: ${prev}"
    ln -sfn "${RELEASES_DIR}/${prev}" "${CURRENT_LINK}"

    cd "${CURRENT_LINK}"
    nohup "./${APP_NAME}" >> logs/stdout.log 2>&1 &
    echo $! > "${APP_NAME}.pid"
    cd -
}

# ── 主流程 ───────────────────────────────────────────
main() {
    mkdir -p "${RELEASES_DIR}" "${SHARED_DIR}/logs"

    fetch_code
    build
    link_shared
    switch_version

    if ! wait_healthy; then
        log_error "部署失败，开始回滚"
        rollback
        wait_healthy || { log_error "回滚后仍不健康"; exit 1; }
        exit 1
    fi

    prune_releases
    log_info "部署成功: ${RELEASE_TAG}"
}

main
```

> ⚠️ **注意**: `ln -sfn` 中 `-n` 参数很关键——没有它，当 `current` 已是符号链接时，`ln` 会在链接目标内部创建新链接，而不是替换。

### 7.2 批量远程执行

**封装 SSH 执行**：

```bash
readonly SSH_OPTS="-o StrictHostKeyChecking=no -o ConnectTimeout=5 -o BatchMode=yes"

# 在远程服务器执行命令
# 参数: $1=host, $2...=command
remote_exec() {
    local host="$1"
    shift
    # shellcheck disable=SC2086
    ssh ${SSH_OPTS} "${host}" "$@"
}

# 向远程服务器传输文件
# 参数: $1=local_path, $2=host, $3=remote_path
remote_copy() {
    local src="$1" host="$2" dst="$3"
    # shellcheck disable=SC2086
    scp ${SSH_OPTS} "${src}" "${host}:${dst}"
}
```

**实战：批量分发配置文件**

```bash
#!/usr/bin/env bash
set -euo pipefail

readonly CONFIG_FILE="$1"
readonly REMOTE_PATH="$2"
readonly SERVER_LIST="$3"

distribute_config() {
    local failed=0

    while IFS= read -r server; do
        [[ -z "${server}" || "${server}" =~ ^# ]] && continue

        echo -n "分发到 ${server} ... "
        if remote_copy "${CONFIG_FILE}" "${server}" "${REMOTE_PATH}"; then
            echo "成功"
        else
            echo "失败"
            (( failed++ ))
        fi
    done < "${SERVER_LIST}"

    if (( failed > 0 )); then
        echo "共 ${failed} 台服务器分发失败" >&2
        return 1
    fi
}

# 批量重启服务
restart_all() {
    local service_name="$1"

    while IFS= read -r server; do
        [[ -z "${server}" || "${server}" =~ ^# ]] && continue
        echo "重启 ${server}:${service_name}"
        remote_exec "${server}" "systemctl restart ${service_name}" &
    done < "${SERVER_LIST}"

    wait
    echo "全部重启指令已发送"
}

distribute_config
restart_all "myapp"
```

`SERVER_LIST` 文件格式：

```
# 应用服务器
10.0.1.1
10.0.1.2
10.0.1.3
```

## 8 脚本质量检查清单

交付生产脚本前，对照此表逐项检查：

| # | 检查项 | 说明 | 状态 |
|---|---|---|---|
| 1 | `set -euo pipefail` | 遇错即停，未定义变量报错，管道错误传递 | ✓ |
| 2 | 所有变量加引号 | `"${var}"` 而非 `$var`，防止分词和 glob 展开 | ✓ |
| 3 | 函数内用 `local` | 避免变量泄漏到全局作用域 | ✓ |
| 4 | `trap cleanup EXIT` | 无论正常退出还是异常终止都清理资源 | ✓ |
| 5 | `usage()` / `-h` | 用户不带参数时能看到帮助 | ✓ |
| 6 | 日志输出到 stderr | stdout 保留给正常数据输出，不与日志混杂 | ✓ |
| 7 | 通过 `shellcheck` | 静态分析无 warning（`shellcheck -x script.sh`） | ✓ |
| 8 | 处理信号 | `trap ... INT TERM`，优雅停止后台任务 | ✓ |
| 9 | 幂等性 | 重复执行不会产生副作用（`mkdir -p`、`ln -sfn`） | ✓ |
| 10 | 注释非显而易见的逻辑 | 解释 *为什么* 而非 *做什么* | ✓ |
| 11 | 常量用 `readonly` | 防止意外赋值 | ✓ |
| 12 | 临时文件用 `mktemp` | 不手写路径，避免竞态和冲突 | ✓ |
| 13 | 路径安全检查 | 操作 `rm`/`find` 前验证目录非空、非 `/` | ✓ |
| 14 | 有锁机制（如需要） | `flock` 防止并发执行 | ✓ |

> **提示**: 可以将此表保存为 `checklist.md`，每次写完脚本后走一遍。

## 9 小结

1. **模板化**：一个好的脚本骨架（set 选项 → 常量 → 库 → 函数 → main）让你在写第一行业务逻辑前就拥有完善的基础设施。
2. **配置外部化**：用安全的解析函数读取配置文件，永远不要 `source` 不可信文件。
3. **结构化日志**：带级别、时间戳、PID 的日志是排查生产问题的基础；颜色仅在 tty 时启用。
4. **并发有度**：用 FIFO 信号量控制并发数，`flock` 防止重入，`wait` 收集退出码。
5. **网络脚本**：curl + jq 是调用 HTTP API 的标准组合；健康检查要有超时和重试。
6. **运维自动化**：磁盘监控、日志清理、备份脚本的共同特征是安全检查 + 幂等 + 告警。
7. **部署可回滚**：符号链接方案让切换和回滚都是原子操作；健康检查通过后才算部署成功。
8. **质量基线**：14 项检查清单是生产级脚本的最低标准。
